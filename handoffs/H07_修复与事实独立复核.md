## 新确认缺陷：P2，发布日期空值绕过当前规则

位置：`shopping_decision/evidence_policy.py:53–62`。

`published_on="未知"` 或空字符串会生成 `unknown_publication`；`published_on=None` 则跳过整个发布日期分支，即使用途为 `decision_support`。在其他准入字段均满足的测试替身上，把 CN-001/003 的发布日期改成 None 后，仍得到路线推荐，且 `judge(...)["success"] == True`。

影响：发布日期缺失的两种表示会产生相反处理；将 JSON 的未知日期统一成 null 时，可能意外放宽准入。当前真实13卡仍有其他未批准状态，因此本轮未发现它们已被这个漏口实际用于强推荐。

修复要求：统一 None、空串和未知文本的处理。按目前明定的规则，对决策用途都返回未知日期；若要允许经人工核查的无发布日期资料，另行明确可审查的例外，不能靠值类型碰巧放行。研究索引用途可以保留不同政策，不应误伤 H03。

最小复现（纯合成元数据，不代表实际许可）：

```python
from datetime import date
from shopping_decision.evidence_policy import metadata_gate

base = dict(url="https://example.org/test", region="CN", target_region="CN",
            captured_on="2026-10-31", reviewed_on="2026-10-31",
            recheck_on="2027-01-01", review_status="reviewed",
            allowed_uses=("decision_support",), purpose="decision_support",
            today=date(2026, 10, 31), source_group="synthetic-test-group")
for published in (None, ""):
    print(repr(published), metadata_gate(published_on=published, **base))
```

本轮结果：`None ()`；`'' ('unknown_publication',)`。修复后同为未知日期时应遵循同一用途规则。
