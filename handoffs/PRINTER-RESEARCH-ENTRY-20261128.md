# 打印机研究入口下一步评估

2026-11-28。角色 Evaluator。状态为只读评估已完成，建议制作可撤销的本机交互样稿。依据为 B05 定向诊断、现有聊天桥和前序项目的合成草案。

## 下一步投入

做一条「接过研究意图 → 本人确认 → 找到第一条决定性证据」的打印机闭环。把此前“换当前任务”的建议放进同一个主窗口。用户在购物端能看到上游带来的目标、已说明的使用情境和待核项，能主动选纸转电子、自动双面、长期不用、预算口径或其他。选择当前关注点只决定问什么，是否为硬条件仍经本人确认。已经明确自己要研究什么的用户沿原入口直达。

交接本身解决的是上下文与选择的连续性，纠正入口解决的是选错问题后如何找回来。单独接 JSON 仍可能把用户带进无关问答。只改问答又无法验证上游目标有没有被正确接住。先按同样资料、同样候选做对照，再决定是否开发正式接收接口。

## 已做的只读小探针

从 `intent-demand-lab` 运行 `python -X utf8 -m intent_demand device-research`，取得实际输出中的合成草案。草案选择在家设备研究，目标是“在家持续处理纸质材料”，携带每周几十份、纸件不得外带等情境，品类为空，批量能力、耗时和预算待核。随后用五次真实 `python -X utf8 -m shopping_decision.chat_bridge` 子进程检查当前入口。每次把上一轮返回的 `state_json` 及当轮字段与答复按桥说明编码传入。

| 操作 | 当前输出 |
|---|---|
| 空会话 | 先问品类，确认字段为空 |
| 模拟用户确认打印机 | 先问用途，品类已确认 |
| 手动将草案目标填入用途 | 先问彩色，扫描尚未确认 |
| 显式提交“扫描必须” | 确认字段新增扫描，当前问题仍为彩色 |
| 显式撤回扫描 | 扫描从确认字段消失，撤回字段保留 |

五步交易均为关闭。以上为人工转录草案目标后的桥侧短探针，未经过自动接收、可见窗口或真人流程。显式提交扫描和撤回用于检查字段能力，不能计为用户从界面找到了扫描问题。本次探针只检查到撤回，完整补证和候选比较待测。

## 样稿与验收

| 场景 | 观察点 |
|---|---|
| 每周几十份签字纸，草案未选品类 | 显示用途与情境，先请本人确认研究品类。若用户确认研究打印机，引导核实是否需要批量扫描、实际耗时和预算。批量使用仅作场景线索。 |
| 来自购物入口的自动双面、长期闲置或扫描 | 自动选题偏离时，用户能主动找到对的任务。确认后分别走型号双面/扫描证据或闲置恢复和维护证据。若具体证据不足，指出对象、项目和下一份可核材料。 |
| 同一草案重复送达，或本人改选、撤回、换品类 | 重复送达保有一个研究入口。采用更新版本或发生实质改选后，旧对比不能继续作现行依据。支持用户看见变化和原因。 |
| 自助、暂缓、无本人选择，或现有明确购买研究入口 | 前三种留在相应路线。明确购物者仍沿现有路径。 |
| 缺证、推广材料、过期价格、冲突条件或误下单 | 验证证据未知如实显示、来源冲突可见、过期价格不能支撑结论、确认边界和交易授权正常。 |

1. 用两个本地走读验证判分。刻意走错问题和误读证据都应该被检出。已披露漏问作为回归，另准备未参与拟题的新样例。
2. 小样稿通过后，建议以 4–6 名新手各两项难度相近但不同的任务，对照现有入口与样稿，交替顺序。每种流程用相同资料、报价时点和候选。记录是否无人提示也能走到具体补证，花了几次无关答复，能否复述一条取舍及适用条件，以及是否把待核误成可买。退出记录原因。
3. 观察到用户更容易找对问题且理解没有退化，再制定一次最小产品改动。本轮若最常见卡点变成某条已确认要求缺型号证据，优先补那条证据；若入口仍找不到，先修入口和措辞。看得见的确认、来源和授权失效边界出现错误时，直接退回样稿。正式实验开始前固定口径并自动记录起止与实际实验区间。
