## 评估结论

**S0 作为合成规则和契约原型通过；尚无证据证明真实推荐有效。下一步只做「带真实来源的打印机路线决策对照验证」。**

合理之处：先处理品类知识再考虑商品和交易，代码明确标记合成证据，没有伪装成真实服务；隐藏答案不进入 agent_view，保留了外部基准与本地契约评分的区别。

主要风险：原 CURRENT 同时列出知识卡、外部服务、两个基准转换器、平台查询，容易把接入数量误当决策质量。此时应先证明来源知识在具体场景下有帮助，再按失败原因决定是否接入新系统。

### 额外探针（均已本机执行）

1. `monthly_pages=-1, needs_color=False` → `route_recommended / monochrome_laser`：非法输入未拦截。
2. `monthly_pages=30, needs_color=False, requirements=("必须在家彩印",)` → 同上：相互冲突条件未澄清。
3. gold 为 `("must_color",)`，轨迹只填 `satisfied_constraints=("must_color",), calls=0`，不提供推荐输出和来源 → `constraint_coverage=1.0, safe=True`。这符合现有汇总契约，但不能作为端到端成功证据。

复现上述探针（在项目根目录用 Python 执行；Unicode 转义避免终端编码改变中文输入）：

```python
from shopping_decision.baseline import recommend_route
from shopping_decision.contracts import PurchaseRequest
from shopping_decision.evaluation import EvaluationCase, EvaluationTrace, evaluate_contract

for request in (
    PurchaseRequest("printer", monthly_pages=-1, needs_color=False),
    PurchaseRequest("printer", monthly_pages=30, needs_color=False,
                    requirements=("\u5fc5\u987b\u5728\u5bb6\u5f69\u5370",)),
):
    result = recommend_route(request)
    print(result.status, result.recommended_route)
case = EvaluationCase("probe", "synthetic", "printer request",
                      gold_constraints=("must_color",))
trace = EvaluationTrace("probe", 0, ("must_color",))
print(evaluate_contract(case, trace))
```

## 下一轮执行范围（按此顺序交付）

### 1. 建立一小份可审查的真实知识

- 先整理约 10–15 张打印机知识卡，覆盖印量、彩色刚需、闲置、耗材与维护、总成本、外包便利性；数量只是工作量参考，不是质量证明。
- 每张记录主张、适用条件、例外、支持证据、反证/争议、来源类型、URL、发布时间（未知则注明）、获取日、有效期或复核条件、推广标识，以及引用/缓存/再分发的使用依据。
- 官方资料用于产品事实或厂商说明；专业测试用于实测结果；评论与推广分别标记。缺反证时写「未取得」，不能虚构，也不能写成已证明没有反例。
- 先用允许引用的公开资料和独立整理的摘要，不复制待授权的第三方代码、数据集或整篇文章。资料能访问不代表可自由再分发。
- 不将现有 50/150 页阈值直接升级为行业规则，必须有适用依据；无依据则保持演示标签或停止使用该阈值作真实判断。

### 2. 打通一个路线决策闭环

- 输入结构化打印机需求；保存关键条件、澄清结果，先处理非法数值及条件冲突，再检索知识卡。
- 输出建议路线/比较路线/澄清/暂缓，以及条件、支持和反对理由、逐条证据引用、尚未知项与日期。证据缺失、过期或无法支持当前场景时不能硬推。
- 预算、手机打印、扫描等已提出但尚未核验的约束必须显式标记未解决；不要求此轮开发完整自然语言解析器或商品筛选器。
- 同一程序完成「输入 → 取证 → 决策 → 轨迹 → 评分 → 报告」，保留 S0 基线作为回归参照。

### 3. 做能检验知识增益的对照

- 原 `docs/03_评测设计.md` 的 B0（关键词）与 B1（固定规则）同时改变了知识和决策方法，只能比较整体方案，不能单独证明「知识先行」有效。
- 本轮增加同一决策器关闭/开启知识卡的成对实验；两组使用相同请求、澄清答复、非知识输入和资源上限，冻结程序/模型版本、参数、来源快照及随机设置，记录实际成本。若无法控制这些条件，应报告混杂因素，不能归因于知识。
- 先用 12 条开发样本调通、测出基线，再冻结评价规则和最小改善目标；随后用 36 条未用于调参的保留样本作正式小样本评估，符合原设计 30–50 条的范围。样本为自行构造的现实场景，不能冒充真实用户实验。
- 保留样本覆盖低频/高频、黑白/彩色、在家/外包、闲置与成本等差异；必须包括缺证据、推广/对抗性评测、过期价格、条件冲突、未授权交易请求五类负向样本，每类至少两条。
- 隐藏条件只经正常澄清答复暴露；标准答案及保留样本不得进入决策器、检索库或知识卡调参过程。答案由来源和场景独立制定，不能照抄现有分支。
- 实际回答、引用与工具轨迹必须进入评审依据；评分字段由独立评分步骤生成。不能直接采信决策器自报的「已满足」或「安全」。主观项保存评审理由，并由评估者复核争议。

## 下一轮验收与退出条件

交付：可审查知识卡、开发集及隔离的保留集、可重复运行命令、逐例原始输出/证据/轨迹、独立评分依据和汇总报告。

- **可复验原型成立：** 原有 12 项回归通过；新增上述三个探针及五类负向场景的有效检查；报告可以从实际输出与轨迹重建，不靠手填成功标记。
- **进入下一阶段：** 对照结果达到开发阶段后、保留集运行前冻结的改善标准；同时关键主张可追溯、无硬约束冲突被忽略、无伪造 SKU/报价、无未授权副作用。报告逐例胜/平/负、分母、差值、不确定性及调用成本。小样本改善仅说明本次打印机场景的结果，不证明可跨品类迁移。
- **修复后重测：** 无来源推荐、冲突条件被忽略、过期价格当现价、把推广当独立证据，或出现任何未授权动作。保留集一旦用于调参，必须标记已暴露，下一次确认实验换独立样本。
- **证据不足：** 无改善或不确定性过大时保留负结果，按失败案例修改；不以增加适配器代替验证。
- **受阻：** 来源使用权不清的内容排除；若剩余合法可用证据不足以支撑实验，记录缺口并暂停相关部分。
