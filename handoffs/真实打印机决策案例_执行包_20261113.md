# 首个真实打印机决策案例：正式执行包（2026-11-13）

**状态：已制定，待执行；本轮未启动实现或外部调用。** 用户要求按已约定的整体方向，将下一大包冻结为可连续执行、统一验收的正式任务。评估者制定 → 执行者实施 → 独立评估者验收。本文件取代原草案成为下一唯一执行入口。

依据：CURRENT.md、[整体审查](../reports/阶段收口与整体瓶颈审查_20261113.md)、[原草案](真实打印机决策案例_下一大包草案_20261113.md)。本机证据处理阶段带遗留收口，原P0.9-B真实目标不改写为完成。

## 一、一个主目标，三项独立成绩

让原真人打印机需求在正常入口得到一份**基于真实销售对象、有证据、有条件取舍、可以修改重算的比较结果**。不要求买下一台，也不强求唯一推荐。

最终分开签发：

1. **真实身份**：至少两个不同型号的销售项，其平台商品/所选配置/厂商型号关系有实际依据。
2. **有据比较**：至少两项对原案有用的取舍理由实际进入输出，能回查适用条件和正反证据，改答后正确重算。
3. **当前可购买性**：只有配置、地区、价格、费用、优惠资格、库存与时间证据足够时才通过；条件不足单列受阻，不由规格满足顶替。

前两项是本包主目标；第三项是有依赖的核价分支。缺报价不阻断身份/内容工作，也不能因此把可购买性标为通过。本包不证明统计上的认知增益、全市场最优、跨品类或生产可用。

执行者在启动后可在上述范围连续推进，不每一步交回领命令。只在确切缺件、依赖的外部授权、费用/工时上限处停相关分支；其他有依据工作继续。

## 四、六步任务、依赖与交付

步骤1明确材料和需求；步骤2与步骤3可穿插推进；步骤4依赖真实身份、地区/预算口径及可访问条件；步骤5复用二者成果并处理遗留；步骤6统一交付。步骤5中的T1修复可在实际接线前穿插完成，**首次把新不可信材料导入受影响路径前须完成**，不必等到纸面步骤5才动手，也不单独成为一个新阶段。

### 步骤1：固定需求与可达材料（参考2工时）

1. 读CURRENT、本包和已有来源账本，记录代码/证据起点与在途Git状态。只核必要环境，不为了“开工”再重复全部历史回归。
2. 沿用2.1需求表；把必要补问集中提出，已答的不重复问，未答不代填；等待答复时可继续材料核查与适用范围明确的内容研究。
3. 列清准确基础信息/SKU合同、实际本机解析/必要展示/最少审计依据、最小原件的可达路径。以前打不开的入口是已知缺件，优先换取得材料的方法，不反复搜索同一页。
4. 明确采用哪条路径：已有海纳原件；新取得且允许使用的最小样本；或有来源/日期/选中状态的允许使用的平台原文、用户主动提供/授权导出材料。不得以页面域名或截图自称替代具体内容核对。

**交付**：同一执行报告内的需求表和材料表，材料逐项记“有据可用/禁止/未知/缺失”、依据和下一实际取得动作。两工时仍缺关键材料，则身份分支受阻并提出具体缺件；步骤3继续，不写虚构接口。

### 步骤2：核实两个真实销售配置（参考8工时）

1. 最低两个不同型号，优先兄弟/惠普各一个。不能以同型号两个卖家凑数；品牌未覆盖要记录，不宣称原品牌比较完整。
2. 每条逐字段记录：平台、平台商品ID、所选SKU或有原文依据的单一销售配置、卖家、全新/二手、主机/耗材、型号、来源及锚点、原观察时刻、核验时刻/复核条件、允许用途。商品ID、SPU、SKU的层级按实际平台合同解释，不转换猜测。
3. 销售配置须有平台权威依据；供应商搜索字段只作线索，厂商官网只作型号事实。标题/参数/选中配置冲突全部保留，未知型号不硬匹配最近旧型号。
4. 首段材料明确后冻结待核样本及选择理由，深入最多6条；优先覆盖目标品牌和已知冲突，不因失败临时换掉难例。旧20条能取得则按原规则审核；取不到，建立新case_id和新分母，旧20条保持未核，不作为永久前置。
5. 留至少一个有据排除/冲突。若真实样本没有异常，可用明确标合成的负向验证边界，不能算真实异常。所有拒绝、受限、失败、人工补录也进索引。

**交付**：完整样本漏斗及两条真实绑定记录。拿不到两个阳性即身份未过；不追加大范围抓取、猜推广ID、重复API查询或用合成数据补数。

### 步骤3：并行形成有据的取舍比较（参考8工时）

1. 从H08人工基线/研究账本起步，初始围绕2–4个来源组查必要主张；按证据充分性取舍，不凑文章数量，同文转载不算独立来源。
2. 回答本例实际会影响选择的问题：低印量/闲置维护、主机与必要耗材/套餐成本组成、微信工作流及型号适用性、品牌比较能证明和不能证明什么。没有价格不算数值TCO，没有故障率不做耐用排行。
3. 每条理由保存原文位置、主张类型、适用条件、支持/反证、来源组、获取日/有效期、允许用途及审核记录。没有找到反证时明确注明并保留来源/样本限制，不为凑正反数量伪造材料。来源未审、地域/型号不适用或推广未揭示时不能进入肯定理由。
4. 先给人工条件比较，再让程序使用同一批有资格的证据。执行者逐条留核查记录，最终独立评估者查资格与内容；不能只改approved字段，也不批量提升旧13卡。
5. 目标至少两项对原案真正有用、实际可回查的取舍理由。证据只能支持局部比较时就局部比较；未知耐用差异等仍明确未知，不能用全defer或通用研究清单满足本步。

**交付**：一份人工比较基线及逐条主张记录，并说明每条理由怎样影响留/排除或下一问。人工研究、代录和自动处理分别标注，不宣称模型自主研究或H1已通过。

### 步骤4：身份明确后核地区价格（参考4工时，条件分支）

1. 仅对已核配置，在地区/预算口径明确且具备实际允许访问条件后核平台权威当前报价；明确主机、运费、必要配件、优惠资格、库存和时间口径。没有条件就受阻，不用供应商检索价/建议零售价/历史截图填现价。
2. 每个进入预算肯定或价格排序的销售项都要有自己的有效报价。只核到一条时，只说明这一条的预算状态，其他未知项不参与跨商品价格排名。
3. 保留地区、配置、卖家、资格、获取日与有效期，不能把导入日当观测日。未确认资格的券不默认可领，套餐与耗材费用不当免费。

**交付**：逐项报价或确切受阻原因。无有效报价仍可交身份/内容结果，但当前可购买性不通过、不批准购买。不得为完成本步自行调用新业务API、登录或绕限制。

### 步骤5：接回正常入口并合并处理遗留（参考6工时）

1. 复用`dialogue_flow.py`、`discovery_pool.py`、`listing_identity.py`/销售配置门禁、`product_compare.py`和逐主张证据入口，仅补本例真实记录需要的薄接线；不重写比较器或通用框架。
2. 真实输入资格必须绑定已核的具体材料/字段/用途，不全局打开真实导入，不让输入文件自报授权或已核状态。合成、历史真实回放、当前获取分别标注；待独立审查的记录保持待审，资格不由外部报告的布尔值授予。
3. 正常入口输出最多三个重点方案；每项可见适用条件、满足/排除/未知、为什么留/不留、正反依据、来源/时间、当前预算与长期成本缺口。评估者无需内部catalog_override注入才能看到新链路。
4. 原案后实跑至少三次关键修改：自动双面、彩印/外包、微信要求或预算中的三种。旧结论和引用随条件撤回/重算；实际真人补答与合成改答分开，不把离线重排说成重新搜全市场。
5. **合修T1/P2**：日期解析及UTC转换不可表示的输入转成逐行拒绝，好行保留，CLI不崩溃。保留11-13原反证、两种坏状态行/双向行序、实际CLI、合法相邻时间和正常撤回对照；不只在CLI外层吞异常，也不发明通用到期年限。不另开小包验收。
6. P3可顺手改善但不扩范围；没有完成证据仍列遗留。现有Java保留兼容，不因文本通过补签GUI。若无实际模型接入，保持规则/人工辅助的真实说明。

**交付**：一条有文档的实际正常入口及完整原案/改答输出、最小代码与专项测试。实现者补真实可用命令；不在本包中假称尚不存在的真实导入参数已经可用。

### 步骤6：一次性交接，统一独立验收（参考4工时）

1. 冻结真人需求、实际素材、人工基线和程序版本；人工期望不调用同一个被测比较器生成。真实材料逐字段可回查，测试替身不混进真实阳性。
2. 正常原案和三次改答实际走子进程。最低负向覆盖缺证据、对抗性评测/推广、过期价格、条件冲突、误下单五组；可复用已暴露回归，按本包实际风险补必要样本。
3. 独立评估者另设计与本例直接相关的新改答、来源冲突/失效、错误身份各至少一例，并审查两条真实绑定和实际理由。数量服务于关键断点，不再无止境增加无关极端样本作为阶段不能结束的条件。
4. 新问题若造成真实错绑、无据肯定、主流程不可用或越权，必须解决；其他问题记优先级和遗留，不自动重开本机基础阶段。
5. 完成末节必要回归，最后一次性交报告/机器索引/交接及CURRENT更新。执行者只自评，独立评估者签发分项结果。

## 五、统一验收门槛

| 编号 | 通过条件 | 不满足时怎样记 |
| --- | --- | --- |
| A1 需求 | 原已确认要求完整保存，不重复问已答信息；必要补问、未知、模拟与真人确认分开 | 漏硬条件或代答不能通过；可不确定但不能替用户选答案 |
| A2 材料资格与身份 | 实际处理用途有依据；至少两个不同真实型号的商品/配置/型号链有平台依据，来源/时间/字段可回查，失败分母齐全 | 缺合同/许可/原件则相关真实分支受阻；不能用原20条摘要或合成阳性替代 |
| A3 有据内容 | 至少两项适用且有正反证据的取舍理由出现在正常输出，能说明留/排除和未知；偏好未覆盖明说 | 全未知/只defer/静态报告未接入口不通过；没有耐用证据就不作排行 |
| A4 正常入口与改答 | 原案+至少三次关键修改实际可运行，旧结论/引用正确失效重算，最多三项重点展示 | 仅内部函数或预写聊天不能通过 |
| A5 当前可购买性 | 所有价格/预算/可购肯定都绑定该配置/地区/卖家/资格/时点的权威有效报价 | 缺报价单列受阻/未过；规格或厂商建议价不能顶替 |
| A6 工程与安全 | T1实际修复及必要回归通过；五类负向不越权，身份/证据不串用，秘密不入材料；购买批准/交易false | T1不拆包，但整包交接时须说明实际结果；越权或无据肯定阻止签发 |
| A7 独立可复算 | 输入、材料版本、人工期望、正常输出、所有失败/调用/工时齐全；独立新例和内容复核有记录 | 执行者自测或测试数量不代替内容验收，未做不标PASS |

**主目标通过需要A1/A2/A3/A4/A6/A7成立；A5单列：**

- 主目标和A5均过：本包各项通过；仍不是交易授权、生产或统计意义的推荐准确率。
- 主目标过、A5受阻：记“真实身份与有据比较通过，可购买性受阻”，不标整包全项PASS。
- 缺两个真实身份或有据内容：主目标未过；可以完成执行交接，但不能以工程/合成测试通过替代。

原P0.9-B/旧20条审核门槛只在对应证据实际具备时关闭；新案例不能倒改旧成绩。

## 六、停止与升级条件
