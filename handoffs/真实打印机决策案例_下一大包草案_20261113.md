## 一、目标及工作量

用原真人打印机需求，完成“必要澄清 → 两个真实销售配置 → 有来源的条件比较 → 修改重算 → 独立内容评审”。身份与专业依据并行准备，地区报价作为依赖明确的分支。

目标是首次真实案例可行性；不宣称已是全自动/全市场/生产系统，也不要求必须买下一台。

建议新包增量工作上限32工时，六步参考分配2/8/8/4/6/4工时。它是方案上限，不是原包剩余量或已执行工时；材料不可得时提前交接，不能靠合成任务填满预算。首次启动时记录实际工时，旧累计未知保持未知。

新增业务API/付费预算维持0；本轮只制定方案。需新调用时先备好准确接口、入参来源、字段用途、目标/次数/费用、凭证作用域和本机保留/删除方案，再按后续明确授权执行。现有一次成功调用授权不自动复用。

只读、只做打印机，复用现有工作区/文本入口/比较器。无账号自动化、持久化会话、加购/填单/订单/支付/退款、外部发信、提交或推送。购买批准与交易保持false。

## 二、六个连续步骤

### 1. 先确定可达材料与必要用户条件（参考2工时）

- 直接沿用真人原案和已知黑白/彩印外包补答，不重复询问已答信息；列出微信具体流程、预算口径、地区等仍未知项，只在影响判断时补问。
- 将此前已确认拿不到的公开正文作为已知缺件，优先安排不同的解阻动作：取得准确官方基础信息/SKU文档、适用于本机解析/展示/最少审计的依据，以及有明确位置/使用范围的最小原件。
- 先核现有材料和可实际取得的路径，不能再用“API可能有该字段”的假设推进。没有精确合同，不猜接口或编响应。
- 两小时内仍缺关键材料时，交一页具体缺件及取得方式/最小实验申请准备；不继续无限搜索同一入口。仍可做步骤3的有限事实研究，不另造合成适配器。

交付：原案需求表 + 材料可达性/缺件表。它们进入同一最终报告，不拆成多份空流程文档。

### 2. 核实两个真实销售配置和一个排除/冲突（参考8工时）

- 优先使用海纳已存在且允许本次处理的原件；原20条能取得则按原规则复核，不能取得可另建合法小样本案例，不作为恢复原20条审核成绩。
- 最低两个**不同型号**，目标覆盖兄弟/惠普各一个；取不到惠普则保留品牌偏好未覆盖，不拿两个卖家同型号凑数。
- 对每条绑定平台/商品ID/选中SKU或有明确依据的单一配置、卖家、新旧/主机属性、型号、来源、观察时间、原文/字段锚点及允许用途。
- 供应商摘要只是线索，厂商原文只证明型号事实，所售配置要有平台权威依据。历史快照只证明当时记录，不声称当前库存/可售。
- 保留一个有据排除或冲突。若真实样本没有该现象，可用明确合成负向验证控制边界，但不能称真实异常已发现。
- 材料受限就停该路径，不借用户会话、绕验证码、解析推广参数猜ID、扩抓取或重复成功业务调用。

交付：逐字段真样本核验及全部失败记录，真实/合成/原20条/新案例分母分别保存。至少两个身份阳性未达到时，本分支不能通过。

### 3. 并行补足能改变选择的决策依据（参考8工时）

- 从已有人工路线基线和账本起步，集中核少量必要来源与主张；先2–4个来源组，不凑文章数量，不把同文转载算多份独立证据。
- 重点核低印量/闲置维护、耗材与套餐成本组成、微信实现方式及型号适用条件；不由Wi-Fi推微信，不由品牌名推耐用，不由建议零售价推预算。
- 每条拟用于比较的主张保留原文位置、适用范围、正反证据、来源/日期、许可/用途和独立审查依据。真实旧13卡不批量提权，不仅改approved字段。
- 先交人工条件比较，再让程序应用；证据只能支持局部判断时就局部比较。缺价格不算TCO数值，缺故障率不作耐用排行。
- 人工代录、来源核查、自动处理分别标注。能够比较的内容必须有实际依据，不能全部填未知而把案例标完成。

交付：至少两项对原案有实际作用、可逐条回查的取舍理由，并明确还有哪些问题无法判断。独立评审有权拒绝不适用的主张，不因本文设数量就凑证据。

### 4. 在身份成立后小范围核价（参考4工时，条件分支）

- 仅对已明确配置，在用户确认地区/预算口径后核平台权威当前报价、费用、优惠资格和库存；无授权/访问条件则受阻，不模拟价格。
- 有资格材料先记录其获取日与有效期，不能把导入日当平台观测日。公开历史截图/供应商检索价不自动转当前报价。
- 对进入预算/价格排序的每个销售项，都要有对应有效报价；只有一条有效报价时，只能说明这一条的预算状态，不对未知项作跨商品价格排名。
- 缺实时报价时仍可通过身份和有限型号/路线比较分支，但“预算内可购买”必须保持未知，整段可购买性不能签发。

### 5. 接到正常入口，合并处理已接受的遗留（参考6工时）

- 复用现有dialogue_flow、候选池、型号比较和证据主张入口；不重造通用引擎或打印机专用新界面。
- 输出最多三个重点方案，显示适用条件、满足/不满足/未知、为什么留/排除、正反证据、来源/日期、预算与长期成本缺口。
- 沿用原案，至少实跑改自动双面、改彩印/外包、改变微信要求或预算中的三次关键修改；真实用户确认与合成改答分开，旧结论撤回。
- **T1/P2日期归一化溢出在接线/导入任务中一并修复**，有专项拒绝/好行保留/合法时间阳性，不单独新开小包；接收新不可信材料前完成这项处理。
- P3锚点合并行序可以顺手改善，但不是进入真实研究的门槛；保持“遗留”标签直到实际有修复证据。
- 无需为内容实验重做GUI；原Java版本待验项单列，不以文本通过补签GUI。实际未接模型时不宣称自主自然语言理解。

### 6. 一次性按真实案例统一验收（参考4工时）

冻结原真实需求、人工参考判断和实际素材，评估者独立查原文及正常输出；执行者不调用同一比较器生成期望值。

主要验收：

| 维度 | 通过需要什么 |
| --- | --- |
| 需求 | 不漏已确认硬要求，不重复问已答条件，未知/模拟补答与真人确认分开 |
| 身份 | 两个不同真实型号有平台商品与选中配置依据，关键字段可回查，失败分母齐全 |
| 内容 | 至少两项有据、适用且实际进入输出的取舍理由；能解释不选什么，证据不足处不强推 |
| 修改 | 实际正常入口改答撤回重算，引用、配置、条件没有串用 |
| 可购买性 | 所有预算/当前可购肯定都能回到该地区/配置/资格/时点的权威报价；没有则不通过本维度 |
| 工程与安全 | T1修复及必要回归通过；缺证据、对抗评测、过期价格、条件冲突、误下单五类负向无越权；批准/交易仍false |

真实阳性和输出内容是主验收，单测数量是回归依据。新发现无关极端输入进入遗留清单，按对真实主流程的影响定优先级，不自动把项目拉回无限边界修补；真实错绑、无据肯定或越权则必须处理。

交付合并为一份执行报告、机器可读案例/来源/分母索引、一份交接、必要本机证据和代码；CURRENT更新。独立评估最后分列“身份”“内容”“可购买性”结果，不互相顶替，不用全defer通过。

## 三、停止点与后续

- 文档/用途/原件拿不到：交明确缺件和下一实际取得动作，身份分支受阻；内容研究继续到现有材料允许的范围。不重复做合成商品或框架。
- 两个真实身份无法成立：不扩大抓取或换样本隐藏失败，身份不通过，决定是否换可用来源/人工受控资料路径。
- 核价条件不具备：价格分支受阻，保留型号/路线有据比较，不制造购买批准。
- 达到新包上限：交已完成和缺件，不扩预算；原工时缺失不补造。
- 首个案例通过只证明有限可行性。其后再做新的打印机案例/小对照检验认知效果，依据真实失败点决定模型接入或自动化；正式跨品类、生产可用和支付不由这一例签发。
