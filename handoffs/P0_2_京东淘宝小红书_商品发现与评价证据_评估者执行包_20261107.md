## 第一瓶颈、假设与执行顺序

第一瓶颈是**可核验的跨平台商品发现和实际销售项数据不足**；第二瓶颈是**评价证据不足，不能解释长期使用/耐用性**。优先顺序如下，执行者可在冻结边界内自行选择少量关键词、重试与必要最小实现，不需要评估者逐条下指令。

1. **京东联盟 P0**：核实应用主体、关键词/详情接口资格、商品池范围、授权主体、展示/保存/消费者比价用途、额度/费用、字段和联盟商品 ID vs SKU 的映射。参考 `jd.union.open.goods.query`、`jd.union.open.goods.bigfield.query`、`jd.union.open.mcp.goods.query`；MCP 字样不意味着有匿名免授权服务。先核官方合同；若具备本应用合法只读权限，再以原三型号中最多 2–3 个查询真实响应。缺权限即登记外部阻塞，不建空适配器冒充上线。
2. **淘宝 P0（独立来源探针）**：核淘宝开放平台/淘宝客对**当前应用身份和消费决策用途**的准入，比较 `taobao.tbk.dg.material.optional`、其升级版与 `taobao.tbk.item.info.upgrade.get` / `taobao.tbk.item.details.upgrade.get` 的适用性。官网标记“不需要授权”是接口用户 session 层的标签，公共请求仍需 AppKey/签名，不代表匿名、无限额或无数据用途限制；优先查商品发现/详情，不假定覆盖淘宝全部商品、天猫全部 SKU，也不将推广价格等同该用户最终到手价。具备权限后最多 2–3 型号只读检索，否则输出前置。
3. **小红书 P1（评价证据研究，不阻塞前两项）**：将官方账号开放、电商商家接口、内容/广告合作区分。已查账号 Scope 仅 `basic_info` 开放，`read_notes` 仍规划中；没有经核实的当前应用全站笔记/评论读取授权。先提交可用授权路径和风险调查；对用户自愿提供或已明确获准使用的少量公开体验材料，只保存自写简短摘要、来源/时间/型号/场景、正反主张、广告和重复风险，不批量搬运全文、评论库或图片。若权限不成立，明确标记不可自动获取，不使用登录 Cookie、逆向/验证码绕过或第三方共享账号。
4. **统一身份与比较 P0**：最小契约区分 `model_id`（厂商型号）、`platform`、`platform_item_id`、`seller_id`、`variant_or_bundle`、`quote_observed_at`、`region`、`source_id`；不可凭同名或相似标题合并，也不能把联盟 itemId 硬转商城 SKU。具体报价另列币种、价格类型、用户优惠资格、运费/必要支出、库存、失效/刷新、地区。评论按型号关联但不作为 SKU 价格。
5. **正常路径和独立复核 P0**：已有 P0.2 条件修复、三型号人工比较和 Java Swing 保存验收不因新渠道任务取消；先用现有正常 Python/Java 入口对照人工基线，然后分开独立验收资料接入、比较内容与 GUI。

## 预算、停止条件与决策

- **最小实验规模**：仅打印机一个品类、原三型号；每渠道最多 2–3 型号、每个接口先 1 次有效请求样本；不为了覆盖数量做泛平台搜索。外部重试只对暂时网络故障做有界只读尝试，建议每个目标最多 3 次，触发平台限制立即停止。
- **工程范围**：先复用 `official_model_discovery.py`、`product_compare.py`、`retail.py`、`research_router.py` 与现有 Python/Java 桥接；只有获得合规的真实响应后再增加**最小**平台适配器。不要先造复杂跨平台调度/大型 RAG/通用智能体框架。
- **立即停止并回交评估者**：申请资质需签协议/付费/个人信息、需要新登录或 Cookie、额度/条款不允许用途、内容访问限制、同名商品无法可靠归一、需求越过只读；不代注册、接受协议或调用受限接口。
- **验收分层**：`CHANNEL_RESEARCH`（官方能力/阻塞调查）、`DISCOVERY_PROVEN`（有权限的真实商品发现）、`QUOTE_VERIFIED`（销售项/地区/用户价格条件齐全）、`REVIEW_EVIDENCE_PROVEN`（合法评价证据可用）、`PURCHASE_COMPARISON`（独立可购买比较）。允许前面阶段单独完成，**不因后面阻塞就伪造 PASS**。
- **权限**：`authorization_commit=false`、`authorization_push=false`、`authorization_api_call=false`（授权业务 API 需对应权利/显式授权后再开展）；不提交、不推送、不修改证据批准字段、不登录、不加购、不下单、不支付。
- **返回评估者**：执行报告应附“与原基线相比真实可发现候选数量/可核验销售项数量/有效地区报价数量/有依据的比较主张数量”、证据链接、失败原因、环境限制、是否值得继续。评估者另做独立复跑并决定继续/暂停/切换瓶颈，不替执行者写业务实现。
