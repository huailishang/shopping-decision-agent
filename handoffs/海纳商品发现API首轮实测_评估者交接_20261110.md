请结合整个项目，而不是只评本次 API 调用：

1. **更新瓶颈排序**：商品发现入口既已存在，当前第一瓶颈是否前移到商品身份/销售项绑定、真实报价与用户地区条件、独立评价证据、API 接入正常用户链路，或数据授权/使用条款？请明确选出一个第一瓶颈，并解释为什么它比其他候选更优先。
2. **核对既有工程状态**：结合 P0.7/P0.8 代码和独立复核材料，区分已经修复/已回归的事实处理、尚未完成的正常入口闭环、尚未通过的 Windows GUI 人工验收，以及外部数据缺口。不要把旧报告里的“未接通联盟 API”机械沿用为当前事实，也不要把 P0.8 的离线用户辅助链接入口误认为海纳 API 已集成。

5. **项目结果边界**：保持购买建议未批准、交易关闭。不要将商品检索成功等同于 SKU 准确、地区到手价有效、库存/优惠资格已验证、商品质量已评测或购买建议通过。

- 本轮只做独立评估、瓶颈排序和下一执行包设计；评估者不得直接修改业务实现。
- 不重复申请 API Key，不重复执行已成功的同一查询。
- 未获明确授权前，不自行调用海纳 API、不扩大数据保存/再分发/模型处理，不将 Key 写入仓库或日志。
- 不读取用户京东/淘宝账号、Cookie 或登录会话；不加购、不下单、不支付。
- 不提交、不推送 Git。
- 原有 P0.8 独立复核状态与已有未提交改动应保留；如评估者认为 P0.8 尚有必须先完成的验收，应说明它与新瓶颈的依赖关系，不得默默覆盖原任务。
