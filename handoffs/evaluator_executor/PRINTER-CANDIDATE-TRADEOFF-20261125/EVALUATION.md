# 本包评估重点

机器检查覆盖确定性错误，人审检查完整取舍的实际新增价值。评估前先核BASELINE，接收执行者快照后复跑冻结命令。新tests/test_candidate_tradeoff.py必须存在且实际运行测试，禁止空发现充抵通过。

## 业务场景

| 场景 | 要核的实际结果 |
|---|---|
| 原低频家庭 | 普通入口有当前研究取舍、有效条件、维护/成本方法与下一信息；可暂平局。 |
| 扫描和双面均无需 | 多余功能不作当前优势；维护成本未知有可查的具体变量或翻转条件。 |
| 扫描为硬要求 | 对应准确事实改变候选资格或缺证，整体结论保留其他硬条件前提。 |
| 彩印硬要求且有明确反证 | 失败候选退出优先研究，其他功能不抵消，下一步不重复查已知彩印结果。 |
| 两款均有硬失败 | 明确原两款无法满足，结束在两款间挑胜者。 |
| 彩印只有缺证 | 待核与不支持分开，保留可查的分支。 |
| 撤回扫描/维护证据 | 只撤依赖结论，独立事实及已确认需求保留。 |
| 无区县/改收货市县 | 保留不受影响的功能与维护比较，动态价格未知。 |
| 合成成本情景变化 | 数学可复算，输入假设可定位，跨阈值后条件分支改变；不能成为真实售价或收益。 |
| 广告指令/过期价/冲突 | 不改写需求，不挑有利证据，不触发交易。 |

逐源审查决定性实际材料，使用预留2次读取；不足以复证则对应事实待核，不牵连其他独立成立事实。HP三条上轮独立复证与Brother受阻状态作为起点，新材料有增量时才再查。

独立选择一条撤回和一条未参与实现的相邻组合，走render_chat检查整体取舍及用户首个问题。不要只核审计状态和结果文字之一。原12案保留适用行为，逐行命题ID或旧显示顺序可合理变化。

同证据看模型是否改善关键因素、候选去留、反证传播和下一行动。逐项引用实际输出，可判无增益。原始响应哈希是HTTP原件的哈希，应另核其提取JSON关系，避免把两个不同表示直接作字节比较。凭据不入评审。

分别裁程序完整取舍、真实资料、模型接通/增益及真人效果。只有参数列表、待核行动单或合成演示时，业务目标不能通过。记录合理的平局、实料不足或实际失败，无须制造推荐冠军。
