## 补测结果

补测固定 2026-11-23，仅替换本地研究结果及日期。两个对照分别显示河南报价满足、日本功能待核，以及日本功能证据匹配时显示满足。实跑输入、结果文本、结构化状态、命题 ID 和异常都保存在原始输出。普通研究后端尚未生产这种结构化包，复现证明的是接入时的程序行为。[重放脚本](evidence/evaluator/replay_extra.py) · [回执](evidence/evaluator/chat-extra.meta.json)

| 发现 | 实际结果 | 判断 |
| --- | --- | --- |
| 无关报价让功能借到收货地 | 河南收货、日本使用。向微信维度加入单位为 CNY 的报价事实，原只适用河南的布尔功能由 `unknown` 变成 `met`，功能命题适用地变成河南。 | AC-02 明确要求插入报价不能改变同一功能事实的地域准入。本案直接反证。 |
| 同样输入会压掉正确证据 | 同样加入报价时，独立且适用日本的功能由 `met` 变成 `unknown`，河南报价仍为 `met`。 | 同一根因双向复现，修正要保留适地证据。 |
| 拆分略过全包唯一性 | 将功能条件 ID 改为 `cost`，同时发布两个同一条件 ID、不同含义和地区的满足命题。 | 全包本应拒绝条件 ID 冲突。逐条件切片分别合法，合并后无法唯一追溯定义。归入下一包校验顺序。 |
| 来源 ID 畸形使聊天出错 | JSON 来源 ID 变成数组后，真入口抛出 `TypeError`。 | 构建来源索引早于安全校验；原资料无法证明适用性时应有待核展示。 |
| 负数报价被发布为满足 | 河南合成购机报价改为 −1，显示 `-1 ≤ 1000` 且 `met`。 | 解析成功不意味着购机报价有效。纳入下一包窄范围成本验收。 |

根因集中在聊天适配层：决定条件地区时先问“这组有没有报价”，再由下层按单位筛事实；切片调用比较门禁前也未做一次全包结构校验。地区应由当前条件的语义与已确认会话决定，再核具体事实能否支持此条件。报价时序修复在本次冻结和补测中未发现反例。
