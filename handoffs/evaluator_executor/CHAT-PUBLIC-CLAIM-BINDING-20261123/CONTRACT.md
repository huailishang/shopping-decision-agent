## 目标

让正常聊天 `render_chat.result_text` 的结构化结论只使用当前会话对应的预算、地区与有效报价。先复现上一包独立发现的三组错误，再一并修复，保留匹配输入下的可用结论。已验结论继续从 `publish_checked_comparison` 产生，`report_json` 保留原始资料和旧文本供审计。对普通聊天后端现有待核流程做回归。

## 验收条件

| 编号 | 通过条件 |
| --- | --- |
| AC-01 预算 | 用户唯一购机上限为 1000 元，购机价格 1300 元。即使资料把 1000 元放在耗材维度，另放 1500 元购机上限，聊天也只能按 1000 元判断不满足，或将购机预算结论降为待核。维度改名、调整顺序和新增同类阈值都不能改变用户上限。条件必须对应购机支出及已确认的预算口径，单项费用、金额碰巧相同的行和资料包自定上限不能充当已确认总预算。用户明确包含额外耗材却缺对应费用时，不声称总预算满足。保留仅有一条且正确对齐的 900≤1000 正例、1300≤1000 反例、合法合成正例的命题 ID。 |
| AC-02 地区 | 价格按已确认的收货地核校，功能按已确认的设备使用地核校。河南收货、日本使用时，合法河南报价仍可作条件比较，只有河南适用范围的微信功能资料必须待核。去掉或插入报价均不能使同一条功能事实改变地域准入。全国报价不能代替河南报价。用适用地域与当前会话相符的功能和报价证明门禁仍能准入，无法独立确定适用地的事实才降级。 |
| AC-03 时效 | 由可固定的聊天侧日期核验引用的报价。2026-11-23 展示时，2026-11-24 才观察到的报价，以及 2026-11-19 已到期的报价均待核。采集日、带时区的观察时间和有效截止日须能形成合理顺序，不能靠资料包自报日期、矛盾采集日或失效区间绕过。按同一聊天日期口径比较，测试需覆盖带时区日期跨界；保留报价确已观察、地区相符、有效期内的合成正例。本包沿用报价以日期为粒度的有效期。 |
| AC-04 回归 | 上一包六项冻结命令均退出 0，原有 510 项及新增测试全部通过。正常 R1 的 2／1／0 条待核记录、微信必须／可选／撤回、预算改答、切品类及旧促单文字隔离均保留。购买批准、交易与实时价格已核标志继续为 false。 |
| AC-05 交付 | 保存三案修复前后 `result_text`、结构化状态和命题 ID，命令原始输出及退出码、差分及保护件哈希核验、实际用时。规范输入与三案均通过后，由 Evaluator 独立复核，Executor 交付时标 `READY_FOR_REVIEW`。 |

阶段顺序为核基线和前测 → 一轮集中修改 → 重放和全量回归 → 交报告。测试仅替换本地研究后端返回和固定时钟，实际调用 `render_chat`。冻结重放验证上一包的精确输入。新增专项覆盖预算口径、同一份功能证据有无报价、地域匹配的功能正例、时区跨日与时间顺序反例等边界。已有测试原样保留。
