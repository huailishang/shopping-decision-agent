# 不加入联盟的商品接口：补充判断（2026-11-09）

- 角色：方案评估者；状态：补充核查完成，未获得接口调用资格。
- 请求：已有京东联盟/淘宝客准入调查，用户要求判断不参加联盟推广时还能如何取得商品查询 API，并考虑兼职/利益冲突顾虑。
- 范围：核对非联盟官方业务接口的真实用途、授权服务商条件，以及没有平台准入时的可用替代；不重复将联盟注册作为唯一建议。
- 边界：不替用户注册、签约或联系平台，不取账号/会话，不调用真实业务接口、不交易、不提交/推送。
- 验收：明确是否有当前可用凭证、是否全站商品搜索、是否只限合作商品池/商家商品，不能把接口存在说成本应用获得权限。

## 结论

不能将“京东/淘宝所有商品接口都必须加入联盟”作为绝对结论。非联盟接口存在，但依赖企业采购、商家经营或其他特定合作关系；这些与面向消费者的全站购物搜索不同。不加入联盟不等于无需开发者注册、应用审核或业务签约。

截至本次核查，未查得普通第三方仅凭消费者登录、无需联盟或其他业务合作，即可调用京东/淘宝全站商品搜索和个人地区到手价的官方公开路径。当前本项目可用凭证、授权请求、有效地区报价仍均为 0；不继续把“加个 SDK”作为已解决权限的方案。

旧淘宝通用搜索与百川文档虽仍可检索，存在历史版本、下线/权限调整或联盟用途限制，不能当成一条现成无需准入的新接口。文档中“免费”“session可选”也不等于任意应用无需 AppKey 和接口权限。

## 服务商必须核实的事项

1. 数据来自平台授权接口、商家主动供给、联盟池，还是网页采集；不接受含糊的“全网官方 API”宣传。
2. 供应方是否有权向本应用交付数据，以及合同是否允许消费者比较、展示、必要保存和模型处理；不能借用别人的 AppKey。
3. 是否仍是联盟数据二次包装、是否含推广转链/佣金安排；“不需要你注册联盟”不能证明数据中立或不含联盟关系。
4. 商品池覆盖、准确销售项、地区库存、价格类型、更新时间及缺失字段；公共参考价不能变为个人到手价。
5. 不索取用户 Cookie/密码；先审条款，再以少量打印机样本验数据，未核准前不采购、不集成、不宣称对接成功。

## 对用户顾虑及下一步的判断

用户所说“兼职风险”可能涉及个人身份/单位约束，也可能包含推广分佣与中立性顾虑，本轮不替其作个人法律或身份判断。数据接入方式与项目是否形成经营/兼职活动不是同一问题，不承诺换成非联盟 API 即可消除该风险。

近期可将“不参与推广分佣、排序不以佣金为依据”作为方案约束。真正需要 API 时，路线限定为适合本业务的平台合作，或已核实供数权的服务商/商家数据。若这些条件暂时不具备，就如实记录无官方通用查询 API；保留通用搜索/用户提供链接作线索、官网核规格、平台允许范围内用户参与的页面核验，不把它命名为平台 API 接通。

本轮没有申请、注册、签约、联系供应方、真实业务调用、账号操作或交易，也没有修改实现和提交/推送。
