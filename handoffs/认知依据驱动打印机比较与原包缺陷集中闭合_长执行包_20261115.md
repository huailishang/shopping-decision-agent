## 1. 本包的任务与继承关系

用户要求：接续“先认知再推荐、打印机与手机如何复用比较程序、权威资料怎样参与认知、现有开源实现”的讨论，结合真实瓶颈，交一个可连续实施、最后集中验收的长执行包。

### S2 最小认知证据：不再只写一篇选购文章

围绕本案做以下选择依据，复用已有可回查材料，按缺口补源：
- 是否必须在家彩印，能否接受外包：用户答案决定硬条件；不能让专业文章覆盖用户明确要求。
- 是否需要扫描/自动双面：具体型号功能事实，以及未列出的功能保持未知。
- 微信打印到底是什么流程：小程序、转App、前置设置、适用地区；Wi-Fi不等于微信打印。
- 低频使用、耗材和长期成本：需要哪些使用量/期限/耗材事实，厂家建议印量和维护说明能说明什么、不能说明什么。
- 预算和可靠性：厂家建议价/当前到手价区别；缺乏独立耐久证据时，不编造寿命、故障率、品牌冠军。

不设置凑数的知识卡数量。验收要求：上述问题均有处理；至少4个维度形成可追溯、会影响当前比较或必要追问的依据，其中至少一个依据来自型号宣传之外的品类比较方法/消费者教育/独立测试材料。可以明确结论是“不足，暂不作此项判断”。

来源使用规则：
1. 消费者组织比较试验支持测试维度/方法及受测样本；监管抽检支持对应产品/批次风险；厂家支持准确型号的规格/流程；使用帖支持具体体验或待调查线索；平台支持当前销售事实。按问题选来源，不按一个总权威分替代证据。
2. 类别认知和具体商品事实分别建记录；一个来源可支持不同范围的主张，但须逐条限定。厂家推广、资助/返佣、样机来源及独立性未知保留；同一试验或转载不伪装成多个独立证据。
3. 对每个重要取舍主动查最可能改变结论的缺点或反证，找不到就记录查询范围与未知，不编造“无负面”。禁止用“用户都说”“行业公认”填缺口。
4. 记录发布日/获取日/版本/地区/样本及访问方式。已有文档的期号和日期也须核对，包括消委会598期相关资料；核不到日期就标待核，不能沿用仓内年份作事实。
5. 公开阅读、原创短摘要与来源链接，和全文缓存、批量建库、模型传输、再分发是不同用途。核实际所需范围；不把未来商业再分发权限当普通公开研究前提，也不越过已知条款/访问限制。
6. 某源无法读取可用明确标注的官方搜索摘录作有限线索，不称已读全文；付费/登录/验证码即停该入口。不得用替代来源支持超出其范围的结论。
7. 本包仅打印机，不为“权威”而查询不相关药监资料，不采购数据、不搭全网爬虫、不批量复制资料库。

输出是可复用的短依据和本案事实引用；不另造一批没有实际消费者问题的空卡片。

## 6. S3—S4：让认知驱动受限的通用比较

### S3 最小选择依据合同

可新增一个小型数据文件，如knowledge/printer_selection_criteria.json，并复用现有来源/商品事实结构。文件名和内部对象由执行者定；以下语义必须齐全，不要求为每个概念另建模块。

| 对象 | 最小内容 |
| --- | --- |
| 选择依据 | 稳定ID、为什么影响选购、适用条件/例外、对应用户问题、依据来源及反证/未知；区分用户硬要求、专业观察、软偏好 |
| 字段描述 | 用户字段/商品字段、类型、单位或枚举、未知语义、需要的型号/市场/测试环境；缺字段不能自动填false或0 |
| 条件表达 | 何时适用、硬条件还是偏好、使用哪种已有受限运算、读取本轮哪个值、结果如何影响资格/追问/解释 |
| 证据引用 | 来源类型/组织/独立来源组、可回查锚点/必要原值、发布与获取时间、适用范围、允许用途、复核状态；价格额外标price_type |
| 版本与状态 | 配置版本/哈希、提取/核对过程、变更与失效理由；结构合法、事实核对、独立评审、购买授权分别记录 |

自动或人工提取的内容先为研究草稿；执行者可逐条核对来源并标明“执行者自核”，不得自行签发最终独立认可或旧卡购买资格。自填approved=true不构成证据。无需为了本包接入LLM；本包先证明人工整理并核源的认知数据能进入比较，不能将此交付称为自主联网认知或自动专业审核已经实现。

禁止在配置中存放并执行Python/Java/脚本、eval、任意表达式、模块导入或网络地址回调。不要新增规则语言、插件市场、向量数据库、复杂工作流框架或第三方模型服务。

只借鉴开源项目的思路，新增代码独立编写；不复制百度知识图谱、球球、ShopSimulator或EComAgentBench源码/数据。NVIDIA/NorthCinder主体代码许可不自动覆盖关联数据、模型及服务；不为本包安装整套参考系统或引入已归档研究项目为运行依赖。

### S4 同一计算结果驱动筛选、追问与解释

优先复用现有product_compare/printer_conditions的合同；必要时独立编写一个小型受限条件模块，例如selection_criteria.py。不在Java另写专业规则，不把每个CASE/DEC名称变成新的Python分支。

本次只实现被上述依据实际使用的基础能力：布尔/枚举匹配、数值关系、集合包含、区间关系，以及有界的条件组合。未知、类型/单位不匹配、不支持的操作、适用范围不足应给明确状态。复杂领域计算留在已审核的明确函数中，不为本次需求即兴生成程序。

必须保证：
1. 先核证据是否适用，再计算已确认硬条件资格，最后展示软偏好和取舍。已知硬条件失败者排除；未知者进入待核组，不能说已满足。无候选就解释缺口，不暗中放宽条件。
2. 计算结果至少保留依据ID、输入值/单位、相关商品事实、适用性、比较关系、资格、证据与未知；解释从这个结果产生，禁止再拼一套固定比较关系或固定预算表。
3. 建议价与到手价分别表示；无地区实时报价时，预算只能显示未核，建议价与预算的大小关系可作为单列背景。建议印量只作适用性研究，不能偷变淘汰硬门槛。
4. 用户新增/修改/撤销条件后，重新计算资格、理由、未知与追问；清除旧依赖结果。输入版本、选择依据版本和事实快照应能在本轮审计中对应；证据撤回/失效/冲突后也重算，不只更新显示时间。验证合法配置变化可用明确的研究/合成实验，不能人为篡改真实型号事实或专业结论来证明数据驱动。
5. 不强行做全维总分、品牌排行或全市场“最佳”。本案输出少量可解释的研究候选、排除项和待核项；至少两条具体取舍直接引用依据及型号事实，其中一条回应微信流程或低频使用的原案关注。
6. 缺口只生成会改变当前判断的问题。已给预算和区间不重复问；未知可靠性不能自动问用户“你是否确认这个品牌可靠”来代替证据。
7. 现有research_router.py继续承担按需研究/复核计划，可补“需要哪些选择依据”的引用；不能把它的元数据计划宣称为已经联网取证。

**通用性小试验最多1有效小时，计入S4。** 用一小组合成手机字段（如存储量下限、重量上限、某功能是否必需）和假商品A/B验证同一比较器；换字段名称/数据描述即可，不增加手机专用if/else、真实品牌/SKU/价格、联网研究、手机页面或商品推荐。测缺单位、边界相等、未知及条件冲突即可；这是工程复用试验，不是第二真实品类成功，也不替代打印机效果验收。若主线受影响，先交打印机，明确该实验未完成。
