# P0.9-B 商品身份与所售配置闭环执行包（2026-11-12）

状态：**已制定，尚未实施**。评估者制定 → 执行者连续完成 → 独立评估者统一验收。本包接续P0.9未完成的AC3/AC4，不代表P0.9已整体通过。

## 1. 目标和为什么现在做

把已有打印机商品发现线索，沿“来源可用 → 平台商品ID → 所选销售配置 → 厂商型号事实 → 正常比较入口”连成可审计的证据链。至少两个不同型号的真实销售项必须有身份与配置依据；没有依据的继续显示待核，不用标题匹配代替所售配置核验。

依据：[本轮修复复验报告](../reports/P0_9_时间绑定独立复验报告_20261112.md)、[原P0.9执行包](P0_9_商品身份与可信证据接线_执行包_20261110.md)、[现有用途缺件](../reports/P0_9_海纳数据用途矩阵与真实样本阻塞_20261110.md)。最新时间绑定修补已获限定通过，R2/R3沿用已测认可，不继续扩HTML关键词或重造导入器。

扩大连续步骤有利于一次交接和统一验收；风险是前面真实材料拿不到，后面做成只有合成输入的空接线。因此本包同时设定真实阳性门槛、逐分支停止点和新旧工作区分，不以“步骤做完”冒充“真实链路通过”。

## 3. 八个连续执行步骤

### 步骤1：固定起点和真实缺口（1工时）

- 先读CURRENT及本包，记录业务模块/证据清单的文件哈希与Git在途状态；复用本轮328项、134项独立检查和Java/H05证据，不把开工时重复全量测试当新成果。仅环境或代码发生变化时补必要基线检查。
- 把本轮已关闭缺陷与未完成AC3/AC4列清。现成海纳合成离线导入、无ID待核区、三原文比较及改答撤回已有，不作为本包新增交付。
- 盘点原20条的**已明确路径是否存在、能否按约定使用**；不要读取未获准原始内容。惠普5条是另一调用的脱敏摘要，不混入20条分母。

交付：在最终执行报告的起点表落一页，避免另建无内容的过程文档。

### 步骤2：核实基础信息/SKU字段合同及实际本机用途（4工时）

先核海纳现行官方开发文档，不凭能力名、截图或检索结果推断接口存在或不存在。公开入口不能读取时记录获取失败；不得猜路径、参数或响应结构。旧11-09文档只标历史证据，不冒充当前合同。

为商品检索、基础信息、SKU三种能力分别记录：

| 必填核查项 | 要回答的问题 |
| --- | --- |
| 官方文档、版本与获取日 | 哪份一手文档支持这些字段？正文/字段不可得就写未知 |
| 地址、方法、入参和错误 | 入参需要商品ID、SKU ID、链接还是别的键？键从哪个已证接口来？ |
| 返回身份层级 | 是供应商自有ID、平台商品ID、SPU、所选SKU还是选项列表？是否明确平台命名空间？ |
| 关联关系 | 检索→基础信息→SKU能否无猜测关联？是否同一商品/卖家/配置？ |
| 型号与销售配置 | 能否绑定主机/耗材、新旧、卖家、具体型号/套餐及选中状态？列表存在不等于已选中 |
| 来源及时间 | 哪些字段是供应商转述，哪些带平台原始依据？观测时间、缓存时间与导入时间能否区分？ |
| 使用范围 | 当前主体能否本机解析、必要用户展示及最少审计？缓存字段/期限、标注/删除义务是什么？ |
| 权限与费用 | 能力开通/调用权限/费用依据是否明确？本包即使明确也不调用 |

本机解析、必要展示、最少审计这三项用途逐项找依据，未知保持未知，不作法律合规保证。未开展的模型处理、训练、再分发与推广功能保持关闭，不把这些未来用途的完整许可当作所有本机工程的前置。上游来源不明时也不能把供应商声称的字段算作平台权威核验。

结果：明确“已能支撑什么、缺什么、能否继续现有材料分支”。最多整理一组精确询证问题和最小实验申请草稿，不发送。不要把整个旧六项询证清单原封不动当本轮发现。

### 步骤3：定义并实现最小销售配置证据记录（4工时）

根据已证字段及现有 `listing_identity.py` 定义最小记录，不为未知供应商响应造通用SDK。平台ID缺失时记录缺失，不能按假设补齐字段。

- 保留平台/平台商品ID；区分商品级与SKU级。淘宝商品ID不等于SKU ID，京东销售SKU也不能按淘宝层级解释。没有所选SKU ID时，只有平台权威原文明确标出单一所售配置才可作为有条件的配置依据，并注明不具备稳定变体ID的限制。
- 绑定卖家、主机/耗材、新旧、实际选中型号/配置、来源URL或匿名材料索引、原始观测时刻、允许留存的原文哈希与字段锚点。标题型号、参数表型号、用户选中配置冲突时全部保留。
- 将供应商线索与平台权威确认分开；厂商官网只能证明型号规格，不能证明某店所售实物配置。平台页面也不能代替独立耐用性评测。
- 缺货地区不能阻断**型号/配置事实**的有限比较；地区价格、可售性与预算资格继续未知。当前 `assess_listing_identity` 的地区字段不得被误用为价格证明。
- 数据输入无权自带批准。核验状态由本机核验逻辑及受控证据记录计算，不照抄供应商/导入报告里的 `identity_verified=true`。字段复核记录与独立验收结果分别保存，不把执行者自评当最终签发。
- 原件缺失、哈希改动、身份键错配、过期/未来观测、失效用途或撤回记录时拒绝升级；同字节新抓取须另记观察事件及复核，不改历史时间。复核期限明确按证据类型标注；本包不能凭空宣布销售项有通用30天保鲜期，历史销售快照始终不声称当前可购。

交付：一个小的证据记录契约和必要校验代码/测试，优先扩展现有模块。缺真实材料时可完成与供应商未知字段无关的校验；不重复实现P0.9已有合成解析。

### 步骤4：盘点原20条并深入最多6条真实身份（6工时，条件分支）

仅步骤2已明确必要用途、且已知路径存在原件时开展；否则此步骤标受阻，继续不依赖真实内容的步骤。

- 按原顺序逐条记录20条的分类、字段是否存在、冲突和缺失，核对已记原响应哈希；不从脱敏摘要推测未见字段。分类总数必须可核对，不静默丢弃坏行。
- 深入样本固定为原报告两个冲突样本、两个淘宝样本、按原顺序两个京东非冲突主机线索；身份不足不替换失败样本。若条目重合或实际无此类别，按原顺序补足并先说明规则。
- 每条给出平台ID/配置/卖家/新旧/型号/主机类型的逐字段核验和来源；至少保留一条实际排除或冲突。原样本不含该现象时，另用显式合成负向证明边界，不混进真实分母。
- 所选配置绑定必须有允许使用的平台权威依据，供应商字段或链接域名只能提供线索。推广跳转参数不解码猜ID，不改写追踪链接，不拿外部站点当平台权威。
- 优先复用现存合格材料和允许只读的公开页面；新API调用仍为0。缺原件、权限或平台内容不可访问时记录具体缺件，不将登录受限写成“商品不存在”。

真实阳性最低门槛：**两个不同型号**，各有平台商品ID、明确所售配置/型号和必要字段来源，能接到厂商事实。只跨两个卖家但同一型号不够。六条内不足两个则停止追加样本，B不通过或受阻，不降低门槛。

### 步骤5：把核验后的销售项接入现有候选池（6工时）

- 保留现有无ID线索区。增量接入步骤3的核验记录；真实响应仅在已证用途范围下局部启用，不全局翻转 `REAL_RESPONSE_IMPORT_ENABLED`，也不靠启动参数或报告内自称“已授权”放行。
- 优先只导入必要、可展示的白名单字段。真实模式、合成模式、历史回放分别标注；本机导入时间不能覆盖原观测时间。若无合格真实样本，仅可证明合成工程能力，真实开关保持关闭。
- 同平台同商品有不同SKU/套餐时分别保留配置；没有SKU/配置键则保留歧义，不合成唯一报价。跨平台相同数字不合并，同型号不同店铺不合成一个销售项。
- 同ID多来源冲突、旧核验记录撤回/失效、型号变更时，重新计算绑定；不因为曾通过就沿用旧字段。错误行有拒绝原因且好行保留。
- 将销售项与已核厂商型号事实关联，但不把海纳价格、score、好评率或店铺宣传升级为硬条件、预算通过或购买理由。
- 不重写Java主决策和既有比较器。无必要依赖变化不引入新的第三方包。

### 步骤6：用同一正常文本入口展示比较及修改（5工时）

沿用 `python -m shopping_decision.dialogue_flow`。如新增读取核验记录的显式参数，由实现者写清实际语法和校验限制，本包不假称尚不存在的参数已可执行。默认启动不联网；不要求评估者通过内部 `catalog_override` 注入才看到新链路。

- 使用原案已知条件：千元内、0–50页/月、家中黑白、偶尔彩印可外包、希望微信、关注耐用、比较兄弟/惠普；具体微信流程、预算口径、地区及耐用差异仍按已有真人确认范围处理。测试补答明确标合成，不写回真人档案。
- 输出最多三个重点型号/销售项，每项显示满足/排除/未知、支持依据、反证/限制、来源/观察时间/复核条件、型号规格与销售配置的关系，以及下一项最值得补的证据。不能只有复杂JSON状态而看不到业务含义。
- 有真实阳性时实际展示至少两个不同型号绑定和一项排除/冲突；仅厂商事实或合成链路时明确标范围，不能称为真实海纳商品比较通过。
- 连续运行原案、要求自动双面、改彩印、取消微信、改预算、条件冲突、不确定回答至少七轮/场景。条件修改撤回旧结论并重算；影响候选覆盖时提示检索待更新，不称离线重排为重新搜索全市场。
- 预算未知和价格未知可分别说明；不因缺地区而抹掉已证型号事实，也不因规格满足而肯定千元内可购。无证据的耐用性/低频成本明确未知。

### 步骤7：独立期望对照与完整回归（5工时）

执行者先固定至少**18个开发场景**，逐字段填写人工期望及理由；期望不调用被测的比较器/身份判定函数生成。老样本作为回归，新场景不能全部从实现分支照抄。每项保存输入模式、期望、实际、差异及失败原因，退出码0但任一 `expectation_met=false` 仍判失败。

至少覆盖以下风险组，可一例覆盖多组但不能省略断言：

| 风险组 | 必须阻断的错误 |
| --- | --- |
| 缺证据 | 原件/用途/平台ID/所选配置缺失或输入损坏仍升级身份 |
| 配置错绑 | 多型号标题、标题与参数冲突、主机与耗材、二手/套餐、SKU只是列表未选中 |
| 去重和冲突 | 跨平台同数字合并、同商品不同变体合并、同ID来源矛盾被静默覆盖 |
| 时间与撤回 | 改观察时间刷新、未来/过期证据、用途或核验记录撤回后仍沿用身份 |
| 报价冒用 | 供应商检索价/历史价冒现价、缺地区/优惠资格却判断预算满足 |
| 对抗性文本与误下单 | 评测/商家文字诱导“忽略限制、已批准、下单”，或外部伪批准字段影响权限 |
| 用户条件 | 自动双面/彩印/微信/预算改答、冲突/不知道，旧结果未撤回 |

保留真实阳性，不得全部变未知求过关；无法取到真实阳性时明确真实分支受阻。只有存在合格的独立评测材料时才作评测事实判断，否则“低频必买/品牌更耐用”等对抗主张应保持未采纳。

执行环境以Windows原生默认Python为主，子进程不依赖外部设置的UTF-8环境变量；全量Python、H05、Java17目标编译及P04/H10各组回归均须通过。WSL按实际改动/兼容风险增补，不把未运行写成通过。

独立评估者统一复验：复算全部执行证据，另加至少**10个未参与实施的新变体**，包含阳性等价输入、身份/配置错绑、撤回、改答、恶意报告和过期价格。真实材料逐字段查原始锚点；合成新例不能代替两个真实阳性。

### 步骤8：一次性交接并更新CURRENT（1工时）

集中交付一份执行报告、一份机器可读核验/场景索引、一份执行者交接、实际变更及必要本机证据。报告内合并步骤2字段合同和用途表，避免重复建空文档。
