# 任务情况独立评估（2026-11-09）

评估结论：项目已具备有限的打印机型号发现和事实比较原型，工程进展可确认；一个真实购买需求的决策效果仍未闭合。P0.7 的现场发现、三款官网主张及受控对照可有限认可，自动规格抽取的可靠性与正常对话接线不能整体签发通过。当前优先级应是修正事实误判、把已核资料接到用户实际入口，再做跨品牌与合法报价验证。

本轮角色为独立评估者，仅核查与留档，没有修实现、修改真实证据批准或开展账号、交易操作。原有未提交改动保留，没有 Git 提交或推送。

## 2. 三款官网主张的独立内容核对

- [HL-10W 官网](https://www.brother.cn/printer/prt/hl-10w)：黑白、无线及微信小程序打印主张有对应；另有购买打印页数、申领耗材的模式。后续套餐费用和约束会影响低印量用户，不能仅按普通耗材购买模式比较。
- [HL-B2188DW 官网](https://www.brother.cn/printer/prt/hl-b2188dw)：无线、微信小程序、自动双面及 TNB020 / DRB020 耗材有对应。
- [HL-B2158W 官网](https://www.brother.cn/printer/prt/hl-b2158w)：无线、微信小程序及 TNB020 / DRB020 耗材有对应。本轮没有足够肯定材料批准自动双面；仍保持未知。

这些肯定主张仅用于限定规格核对。厂商建议零售价没有变成成交价，耐用性仍缺独立证据，实际微信设备连接没有测试，三款均没有有效地区到手价。没有修改人工基线或真实知识卡的批准状态。

独立回源的目录和三详情全部 HTTP 200，并保存当前原始 HTML 到忽略目录 `data/raw/assessment_20261109/`，来源、时间、路径和哈希见 [来源记录](assessment_sources_20261109.json)。本次 4 页哈希均与执行者历史摘要不同；现有 P0.7 代码只返回摘要，没有保存原始响应，既有 `data/raw/` 也没有提供对应原始文件。因此本轮能够确认当前主张和新的取证记录，不能完整重放执行者当时的原始字节与抽取。该缺口不改变当前文字已经回源对应的结论。

## 3. 本轮发现的实质问题

### R1：规格抽取把否定、其他型号和脚本文字当成当前型号的肯定事实（高优先级）

位置：`shopping_decision/p0_7_official_details.py:38`、`:54`、`:59`、`:64`；文本收集器 `shopping_decision/official_source_check.py:38`。

解析器在型号标题之后取一个宽泛文本段，再做肯定短语子串匹配。标题核对能排除整页错型号，但不足以保证正文每句话属于该型号，也没有识别否定语义或排除 script 内容。

| 新合成输入，均放在合法型号标题后的正文 | 实际结果 | 应有行为 |
| --- | --- | --- |
| 本机不支持无线网络连接，仅支持 USB | wireless=true | 不得确认支持 |
| 本机不支持微信小程序直连，支持远程打印的是其他型号 | wechat_miniprogram=true | 不得确认支持 |
| HL-B2188DW 标配 A4 自动双面；HL-10W 不支持自动双面 | HL-10W auto_duplex=true | 不得跨型号借用 |
| 无线支持文字只出现在 script 字符串中 | wireless=true | 不得用脚本文本确证 |

4 个新样本均出现误判，不能与 285 项旧测试合并成“全部通过”。这是构造故障输入，不是在断言当前三张官网实页已经出现同样错误；但足以否定抽取器可可靠处理这类内容的结论。它会将本应未知/不满足的硬条件判成满足，应先修再扩型号。

### R2：新事实尚未进入正常对话入口（主线未完成）

位置：`shopping_decision/dialogue_flow.py:164`、`:191`。

`compare_dialogue(state)` 默认仍调用历史目录快照。CLI 主循环也不提供已核新目录，因此三款新型号只具备黑白类别事实，无线和微信仍是未知；只有调用内部 `catalog_override` 才使用 P0.7 新详情。Java 正常入口重放仍比较原 5 型号。

这不是撤销已有工程交付，而是说明最新模块尚未成为用户实际使用的完整链路。原动态对话包要求的“一条正常入口 → 发现 → 取证 → 比较 → 改答撤回”还未验收，不能只用内部注入演示代替。

### R3：关键套餐、详情来源和时间没有完整带到比较结果（高优先级）

位置：`shopping_decision/p0_7_official_details.py:132`、`shopping_decision/product_compare.py:137`。

HL-10W 的 `billing_model`、详情获取时间和响应哈希写入了目录内部的 `manufacturer_detail_evidence`，但比较器没有将该对象带给候选输出；普通基本条件比较也不提示按页付费这一重要差异。页面级来源 URL 仍在，耗材列表也在，但不足以展示这种长期费用条件和逐型号取证时间。

独立合成导入还发现：把详情时间改成 2099 年，导入不拒绝，比较器按目录总日期仍能输出 `specs_matched_not_purchase_approved`。这是内部记录校验缺口，不是本轮真实网页带了未来时间；也没有导致购买获准。详情时间应独立验证，不能仅用旧目录日期判断新事实是否有效。

### R4：不确定回答与条件变化的处理仍有局部缺口（次优先级）

- 微信方式和预算范围明确答 `unknown` 后，`next_questions` 返回空列表，但内部比较仍列出这两项及地区问题。用户可以保留不确定，不应被强迫反复回答；应统一展示未决状态、影响和可选下一动作，避免外层显示无问题而内层仍需确认。
- 已确认 `needs_color=false` 后又在要求中新增“必须彩色打印”，系统同时应用黑白与彩色条件，返回普通事实比较，没有请求确认新旧条件如何处理。需要明确最新答复覆盖还是进入冲突确认，避免将需求冲突解释为市场无匹配。

这些是新合成诊断，并非新的真人试用成绩。详细输入/输出见 [独立探针](assessment_probes_20261109.json)，可用 [留档脚本](assessment_probes_20261109.py) 复算。

## 4. 对当前瓶颈的判断

合理之处：从静态 eMCR 转向实际官网型号取证，复用原三态比较器，且没有把官网价或规格匹配包装为购买批准，方向成立。三款新型号具有真实外部出处，已经比固定 5 型号演示推进了一步。

潜在风险：继续增加品牌、样本数量或界面，可能掩盖抽取误判和入口脱节；48/48 对照复用同一个比较器，也不能发现双方共同遗漏的套餐解释和证据展示问题。仅把困难归为“没有商品库”或“差实时价格”也不完整：真实需求的路线依据仍为 0，独立耐用性、低印量长期成本和跨品牌取舍仍需内容证据。

平台价格权限缺失会阻止确认预算与可购买性，但不必阻止已授权的规格比较、内容核对和负向修复。当前不能选出一个可信购买方案，既有外部供给原因，也有本机事实处理和主线集成原因。
