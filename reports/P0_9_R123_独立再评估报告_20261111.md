## 2. 新增独立诊断仍发现什么

### R1 / P1：自动提取仍能把未成立主张送进硬条件判断

本轮新增12个HTML场景，5个符合预期、5个错误肯定、2个明确阳性丢失。都是手选诊断，不是随机网页质量/总体错误率；也不能据此断言三份真实官网页面发生同样错误。

| 输入 | 实际 | 应有处理 |
| --- | --- | --- |
| “本机是否支持无线网络连接？” | wireless=true | 问句不是产品主张，未知 |
| “如果本机支持无线网络连接，请先连接路由器” | true | 条件句不证明前提成立 |
| 正文先肯定，后更正“无线网络连接不支持” | true | 正反冲突，不给确定肯定 |
| 其他型号章节标题后隔3个中间段落再讲无线 | true | 不得因最近3块没有型号就遗忘所在小节主体 |
| `style="display:/**/none"`中的无线文案 | true | 内联隐藏内容不能升级为可见证据 |
| 标准模式下`.WIRELESS`隐藏规则与`class="wireless"`不匹配 | 未知 | 区分大小写，避免误隐藏可见阳性 |
| “本型号不支持扫描。支持无线网络连接。” | 未知 | 不同功能、不同句子的否定不能串到无线 |

另外5例（可见后代样式、其他型号否定与当前肯定、未知CSS显式拒绝、hidden属性、行内拆分否定）符合预期，保留这些控制。

定位：`official_detail_text.py::supported_phrase`未区分问句/条件句与断言；`_scope_is_other`只回看最近3个文本块；`_has_current_negative`的否定方向和字符范围不能表达完整句间关系；内联样式未统一处理注释。标准模式大小写测试显式加入`<!doctype html>`，避免混入quirks-mode规则；语义依据[W3C类选择器说明](https://www.w3.org/TR/selectors-4/#class-html)。

**已做离线完整路径反证**：构造上述问句→`parse_detail`→`enrich_discovered_catalog`→`compare_products(required={wireless:true})`，HL-10W实际得到`required_met=[wireless]`及`specs_matched_not_purchase_approved`。这表明错误不限于一个解析器字段，能影响硬条件判断；购买批准仍false，未发生交易。

### R2 / P2：字段类型补强后，内容隔离和异常逐行处理仍有缺口

- 把合成推广URL作为**普通字符串**放入`brand_hint`，长度小于120，二次校验仍接受；URL及合成追踪标记实际到达正常CLI。嵌套对象问题已修，但“字段是字符串”不证明它是品牌。不是实际密钥泄漏，也没有执行URL或提升交易权限。
- 将`identity_status`设为对象，集合成员判断抛`TypeError: unhashable type: dict`。加入1条合法线索和1条此类坏线索后，CLI返回`discovery_report_unavailable`、合法线索也全部消失。应用未崩溃，但不是承诺的坏行拒绝、好行保留。

定位：`discovery_pool.py:76`仅检查提示字符串类型/长度；`:82`在枚举类型确认之前作集合成员判断。应先校验基础类型、逐行捕获并计数；对于品牌/店铺等字段的完整URL与追踪内容，明确拒绝或删除并留最小原因，不原样进入审计/用户输出。不要把`synthetic_test`标签当成实际来源真实性证明。

## 3. 为什么不能只继续补关键词

上轮14例全部转绿证明执行者确实修了已知问题；新输入再次暴露问句/条件句、长段落主体和否定关系，说明问题已超出增加几个型号或CSS词条。完整HTML/CSS渲染与自然语言事实识别都不是本阶段应重造的通用能力。

当前有两条必须分开的路径：

1. **已逐字段核对、原文/型号/日期固定的三份官网事实重放**：可以继续作为限定型号事实比较的基线，不因为通用抽取失败而删掉这些有用阳性。
2. **新页面/检索摘要的自动抽取**：只能形成待核主张；尚未有独立字段核对/受控模板验证时，不应仅凭厂商域名、命中功能短语和一个哈希就自动进入满足/不满足判断。

下一步建议增加最小事实准入记录，而非重建审批系统：绑定型号、字段值、原始哈希/定位、获取日期/复核期、核对依据与适用用途。该资格只允许“厂商文字规格比较”，不自动升级路线知识、耐用性、数据复用许可或购买批准。已有证据批准字段不得批量放开。

## 5. 下一执行段：继续P0.9，收窄自动事实准入

建议一个8–12工时的有界续段；先记已用工时，仍遵守原包预算，不默认扩至新大包。由执行者实施，独立评估者验收，不逐个等待检索命令：

1. **先截断错误升级**：新自动抽取标为待核主张，未取得字段核对依据时，不能被`enrich_discovered_catalog`/普通比较作为已核真/假使用。三份已核原文重放保持可用，不改购买批准。验收必须包含“问句→抽取→接线→比较”的端到端负例，以及原始真实阳性，不能全改未知。
2. **收口R2**：URL字符串/追踪内容不进入品牌店铺等提示；枚举先验类型，坏行拒绝计数且合法行继续展示；增加混合好坏行CLI回归。
3. **准备真实身份实验**：只读核基础信息、SKU文档，明确入参ID来自哪里、返回ID/配置/来源时间/缺字段、两接口之间如何关联、哪些字段只是供应商转述。用途清单仅列实际要做的本机解析/展示/必要审计，不以未使用的训练/再分发权利为前置。已有询证草稿可整理，未授权不发送；不读取Key或试调用。
4. **一次性交付**：运行修后原始12例+旧14例、真实三份来源阳性、好坏行隔离、Windows默认全量及普通CLI。独立验收看“错误自动主张未入判定”，不要求规则解析所有自然语言/所有CSS。第三段没有可读文档时交具体缺件和接口合同草稿，不造SDK或模拟真实身份成功。

本段新增海纳业务调用0、付费0，不重复登录/连通测试；真实实验调用需另有明确授权/限额及适用用途依据。完成后先争取“限定事实比较链路”通过，再开展真实身份/报价；P0.9整体必须保留AC3/AC4阳性门槛。
