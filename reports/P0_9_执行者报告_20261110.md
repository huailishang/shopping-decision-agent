## 二、第一段：P0.8 可信度缺口修复

### 1. 型号归属

修改 shopping_decision/official_detail_text.py：

- HTML 正文抽取改为标签栈，正确处理嵌套隐藏节点，不再只用单一 depth 计数。
- 在解析前提取简单 CSS class/id 隐藏规则；识别 display:none、visibility:hidden、content-visibility:hidden、opacity:0，以及 hidden、aria-hidden、行内隐藏样式。
- 型号正则改为可识别紧邻中文的型号，例如“仅限HL-B2188DW”。
- 正向主张按所在语句检查前后文；同一句出现其他型号、后置“仅限/仅适用于其他型号”或否定时，不把主张归给当前型号。
- 保留可见正文阳性；没有把所有字段一律降为未知。

### 2. 来源闭环

修改 shopping_decision/p0_7_official_details.py 的 load_reviewed_local_replay：

- 普通文本入口不再读取 P0.7 的旧详情摘要。
- 改为读取 P0.8 来源清单 reports/p0_8_refetched_official_sources_20261109.json。
- 对三款型号逐条从 data/raw/p0_8_official_details/{SHA256}.html 读取原始 HTML，校验文件哈希、型号 URL、观测时间、抽取阳性字段和套餐模式后重新 parse_detail。
- 原始文件缺失、哈希不符、清单不完整、字段重放不一致时拒绝，不给旧摘要换哈希或时间。
- 普通入口遇缺失/损坏/无效证据时明确降级为旧目录快照，并输出 source_warning；不偷偷使用旧详情摘要。

实际正常回放：HL-10W、HL-B2188DW、HL-B2158W 三份 P0.8 HTML 均哈希匹配，普通入口输出的三条逐型号详情哈希与 P0.8 原文一致（3/3）。

### 3. 过期详情

修改 shopping_decision/product_compare.py：

- 单独计算 manufacturer_detail_age_days。
- 逐型号详情超过 30 天时，来自该详情 URL 的当前功能事实降级为未知；不改写原始事实对象，历史记录仍可审计。
- 即使目录 recorded_on 被刷新为当日，也不能让过期详情恢复当前有效。
- 输出 manufacturer_detail_is_stale 供调用方识别。
- 本轮模拟 2020 年详情、目录日期保持新鲜：wireless 从 required_met 移至 required_unknown，状态 needs_verification。

## 四、第三、四段：薄导入契约与候选池接线

新增 shopping_decision/haina_ingest.py：

- 只允许 source_mode=synthetic_test；source_mode=real_response 在 REAL_RESPONSE_IMPORT_ENABLED=False 时直接阻断，不解析 payload。
- 限制输入体积、行数、观测时间和业务码。
- union_spec 字符串只用 json.loads 安全解析。
- 仅抽取标题/规格型号候选、品牌/商城/店铺/类别提示、推广链接类型、新旧/套餐/耗材提示和待核字段。
- 不保存完整推广 URL，不解析追踪参数，不猜平台 ID。
- 不导入价格、历史价、score、评论数/好评率、图片；不采信外部传入的身份、报价、购买或批准字段。
- 所有输出都是 source_lead_only，不是已核实商品。

修改 shopping_decision/discovery_pool.py：
- 支持 Haina 离线线索报告。
- 无平台 ID 的线索单独输出 unverified_source_leads，不静默丢弃、不进入正式 candidates、不参与价格比较。
- 只接受 synthetic_test 模式的 Haina 报告；真实响应被阻断报告会计入 blocked_report_count。

- 单一型号候选但平台销售项未核：1；
- 耗材而非主机线索：1。
- 导入线索 4；平台候选 0；平台 ID 0；报价 0。
