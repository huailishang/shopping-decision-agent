## 2. 逐项目源码分析

### A. Playwright MCP：可借用浏览器通道，不是商品搜索引擎

- 原始 `browserFactory.ts` 区分远端、CDP、扩展、隔离和持久浏览器；`extensionContextFactory.ts` 使用 CDP relay 连接已经安装扩展的 Chrome/Edge 浏览器，属于“连接到浏览器”而不是平台商户商品接口。
- **我们可用的功能点**：用户主动授权的页面查询与销售项复核，使用浏览器快照提取页面里可见的**商品 URL/标题/选择项/时刻**，转入本项目的“待核候选”；继续由商品证据与硬条件门禁决定能否推荐。
- **重要风险**：扩展模式能接触当前登录标签页，权限高；页面中可能出现用户隐私、恶意内容或禁止脚本访问的提示。避免持久化 Cookie、远程共享浏览器端点、跨标签/跨站自由访问、自动绕验证码。商品搜索平台条款及显式用户授权还须独立审核。
- **本轮实现状态**：**未接入浏览器、未读登录态**；只把“用户主动提供的京东商品链接”做成离线低信任候选入口。技术基础足够，但尚不能宣称前台授权浏览器验收完成。

### B. JD-Shopping-MCP：能辅助发现，但不能自动证明商品与价格

- `src/jd.ts` 的 `searchProducts` 优先公开 `search.jd.com`，失败则 Bing `site:item.jd.com` 回退，再尝试 `p.3.cn/prices/mgets` 批量参考价；`getProduct` 把商品页与价格两类返回聚合。
- `src/types.ts` 把 `jd-search`、`bing-fallback`、`proxy`、`jd-price` 等来源记录在数据中，商品返回允许 `null` 价格并标 `warnings`。这比直接只拿一个数字可靠。
- **缺点**：`src/parser.ts` 的通用 `\b\d{6,20}\b` 兜底会从模糊文本中提取任何长数字，可能把电话、订单号当 SKU；公开价格不含用户券后/地区/PLUS/服务成本；Bing 链接不是京东站内排序；代理的合同、来源身份不自动可信；无明确许可证。
- **可借功能点**：对第三方 `jd_search_products` JSON 进行**严格 URL+编号核验、来源分级、去重、冲突检测**。即使数值存在，也不能直接进入“真实地区报价”。
- **本轮实现状态**：已完成**独立开发**的 `shopping_decision/discovery_ingest.py`，可离线消费上述结构但不联网；不调用该项目的 Cloudflare Worker，也不复制源码。

### C. mcp-cn-commerce：最值得借鉴“分层可用状态”而非照搬商户工具

- `shared/normalizer.py` 的 `UnifiedProduct` / `ProductSku` 以平台 ID、变体、价格（分）等字段区分数据；订单/商品/评价统一 schema、保留 warnings/source_values；其他共享模块有明确限流、重试、脱敏与指标。
- 项目明确区分 **工具注册**、**已核业务合同**、**SDK 可调用**、**真实商家验收**。其 Core 0.1.6 总计8个平台入口、155个工具（含历史/未支持），**全部 SDK `live_verified=false`**，注册数量不能代表真实商家可用。
- **重大适用性差异**：其京东/淘宝是**有商家主体授权的订单、售后及经营数据**，不是面向任意消费者全商品池检索；用户登录京东商城不能转换成商家开放平台商户权限。
- **可借功能点**：为 JD 官方联盟、淘宝联盟、公开 MCP、用户授权浏览器保留独立能力状态与来源等级；不能只因为某个 MCP 提供 `search` 工具就认定已获得平台权限和核价资格。
- **本轮实现状态**：`SOURCE_READINESS` 是安全默认能力表，所有真实平台授权和核价标记均 false；它只是离线开发时的安全检查，不是应用平台真实状态自动探测。

## 3. 本轮实际代码交付（不是“空适配器”）

新文件：

- `shopping_decision/discovery_ingest.py`：`parse_jd_item_url`（完整 HTTPS + 精确 JD 域名/路径）、`ingest_jd_search_snapshot`（处理已获得的公共搜索快照，限20项，拒绝无关数字/错误SKU、标记 Bing/代理、跨品类通用、永不提供已核价）、`ingest_user_jd_item_link`（用户主动粘贴链接的离线待核身份）与 `SOURCE_READINESS`（源能力默认拒绝）。
- `tests/test_discovery_ingest.py`：12个纯离线测试，覆盖假域名、SKU 冲突、Bing/代理/搜索来源洗白、重复不同标题、时间缺失/未来、提示注入、未授权价、跨品类商品、用户链接以及默认权限关闭。

实际落地的是**商品发现数据入口之前的边界**，而不是生产平台的`search.jd.com` 调用；本模块不连网络、不获取密码、Cookie 或地区价格。当前已有 `listing_identity.py` 的正式联盟销售项核验只接受 `JD_UNION` / `TAOBAO_TBK`，公开 MCP 返回 `JD_PUBLIC_UNVERIFIED`，故不会绕过既有正式平台身份门禁。

## 4. 评估者需要验收的三件事和下一步

1. **目前已做的测试**：新12项和全量回归通过；只证明数据门禁有效，**不**证明真正接通京东或商品推荐覆盖。
2. **授权试点的优先级**：下一包先确认 JD 联盟或淘宝联盟的最小搜索应用准入，获取2–3个明确有来源的真实官方搜索/详情记录，然后对照此离线转换与既有 `listing_identity` 做字段差距审查；不要继续以官网品类目录当主要发现来源。
3. **浏览器试点的优先级**：用户明确同意、平台条款允许时，单次读自己的已登录页面（最多3–5个手选销售项），取页面里的商品链接与选中配置；由用户核实隐私与价格上下文，不能用后台脚本批量扫全站、绕风控、保存账号会话。

### 实验不能跨越的结论

**现阶段 `DISCOVERY_INGEST_WORKS`（离线结构通过），不等于 `OFFICIAL_DISCOVERY_LIVE`、`LOGIN_BROWSER_APPROVED`、`REGIONAL_QUOTE_VERIFIED` 或 `PURCHASE_APPROVED`。** 原打印机案例仍无有效地区到手价，保持 defer；交易关闭。未提交、未推送。
