# 整体瓶颈与公开商品数据路线评估（2026-11-08）

角色：评估者。结论属于项目诊断和方案评估，不是数据接入、真实推荐、平台业务或跨品类验收。

## 1. 评估结论

**当前最缺的是一条能被独立验证的“需求 → 有依据的选择条件 → 外部候选发现 → 准确型号事实 → 条件比较”链路。认知质量和外部供给都尚未验证完成，不能归因为只缺商品数据库。**

近期商品端的直接断点更明显：平台真实搜索尚未打通，多源线索池尚未自动驱动正常打印机比较；认知端则仍没有获准用于原案路线建议的证据，少量人工比较也尚未完成独立内容验收。工程回归领先于实际决策效果验证。

模拟库适合作为可控实验条件，定位缺陷；它不能独自证明从外部自主发现商品。eMCR 属于真实商品目录构建的固定检索基准，不能简单叫作人工编造的模拟商品库；Open Icecat 属于商品内容目录，也不等同于中国商城当前可购买销售项。

## 2. 本仓实际依据

| 环节 | 已有依据 | 还未证明什么 |
| --- | --- | --- |
| 需求与澄清 | 打印机结构化输入、区间、硬要求/否定等回归；正常入口仍为专用品类规则 | 陌生品类、多轮隐含需求的理解质量；不是已有大模型自主规划能力 |
| 购物前认知 | 研究路由、主张门禁、三型号人工条件比较；知道哪些材料不能当依据 | 针对低印量/长期闲置的可靠路线取舍、耐用性及总成本判断能改善真实决策 |
| 外部商品发现 | 历史兄弟官网目录发现9型号；JD/TBK格式导入、用户手选链接及去重 | 广泛跨品牌/跨品类自动检索、合法实际商城响应与覆盖率 |
| 型号事实及比较 | 5款厂商事实；布尔硬条件三态比较；人工基线3型号 | 从新来源自动提取数值、单位、型号变体，再进入正常比较 |
| 可购买性 | 报价资格隔离与缺失说明 | 当前地区价格、配置、卖家、库存和运费符合原案预算 |
| 效果评估 | 历史工程回归与负向探针 | 在有足够证据的阳性任务中提供有用比较；全程暂缓不能替代效果验收 |

代码审读重点：

- `shopping_decision/research_router.py` 产出研究计划，不自动联网取证；`validation.py`、`web.py` 正常决策仍限制打印机。
- `shopping_decision/product_compare.py:compare_products` 的硬要求/偏好是布尔映射，不能直接承接尺寸、噪声、容量等数值区间和单位条件。可以沿用其满足/不满足/未知语义，但需要最小适配。
- `compare_printer_request` 仍从固定 `printer_products_official.json` 读取；不能把多源线索池已有离线演示算作已接入普通决策。
- `shopping_decision/discovery_pool.py` 限定三种JD/TB来源、平台ID和网址形式；eMCR记录ID和Icecat型号ID不可冒充商城ID。型号事实与销售项身份需要保留不同角色。
- `reports/P0_2_三型号人工比较基线_20261106.md` 已给连接工作流与耗材取舍，但明确缺独立长期耐用/实耗研究；这部分不能由商品规格或检索分数补足。

本轮独立运行 `evaluate_input`：沿用0–50页、黑白、彩印外包、1000元、微信偏好条件，收货地使用“合成市”。结果为 `defer`、获准证据0、候选5、预算状态均 `unverified_no_authorized_live_quote`、可购买候选0、购买批准false、交易false。这是结构化接口回放，不是新真人确认、真实渠道调用或GUI验收。另用未知外部来源标识调用候选池，报告被阻断，符合当前来源白名单；不代表新数据源接入测试通过。

## 3. 两个外部数据源的核查

以下官方资料于2026-11-08查阅。网页可访问性、接口实际能力和本项目授权分开记录。

### eMCR

- [官方数据卡](https://huggingface.co/datasets/alibabagroup/eMCR/blob/main/README.md)：由真实淘宝目录构建的中文多条件检索诊断基准；查询采用受控的大模型辅助生成，并非1399条完整真人购物会话；数据卡标注Apache-2.0。
- [官方文件](https://huggingface.co/datasets/alibabagroup/eMCR/blob/main/data/emcr_benchmark.jsonl)约119MB；[目录](https://huggingface.co/datasets/alibabagroup/eMCR/tree/main/data)含图片，约13GB。先取文本做限定实验有可行性；未读取图片就不能汇报完整多模态成绩，应单列文本可判断子集及排除数量。
- 本轮仅通过公开文件流读取首个16KiB并解析首行，未留存全量数据或图片。首行同时有商品字段、`query`、`anchor_id`、`anchor_text`、`score`、`reason`、`score_m1/score_m2/score_arbiter`。**商品检索输入应剥离查询关联、锚点和评判答案；评测查询可提供给被测系统，标签及相关解释只给评估器。** 全文件结构一致性与ID重复冲突尚待实际接入检查。
- 目录内匹配只能证明固定语料上的检索表现。历史价格字段不具备地区实时核价资格；单条相关性评分也不是低频耐用、长期成本或购买价值证据。

### Open Icecat

- [Product JSON官方说明](https://iceclog.com/manual-for-icecat-json-product-requests/)（页面标注2026-10-13更新）：公开演示账户可查询部分Open商品；接口一次返回一个已识别产品的资料。单品查询成功只能证明详情获取，不能证明从用户需求发现未知型号。
- [索引官方说明](https://iceclog.com/manual-icecat-product-xmls-batch-processing/)（页面标注2026-10-27更新）：目录索引可支持品类筛选与增量同步；包括Open目录在内的索引下载需认证。`On_Market`表示至少有分销商确认分销，不能当作本用户收货地现货。
- [官方MCP说明](https://iceclog.com/how-to-connect-claude-to-icecat-mcp/)（页面标注2026-10-22更新）：需Channel Partner账户与令牌；已列工具主要围绕品牌+产品代码或GTIN查询。不能由“MCP已存在”推成中文多条件全库搜索已经提供。
- **用途许可是当前方案的实质前置。** [Open Content License](https://iceclog.com/open-content-license/)公开版本1.4（2026-02-11）第10条涉及训练、算法模型生成、自动合成内容和生成式AI框架下游商业使用限制；[公平使用政策](https://iceclog.com/open-icecat-fair-use-policy/)也对未经商业许可的AI训练采集作出限制。不能缩成“只要不训练就能任意用于商业AI”。官方MCP技术文档存在，仍不足以确认本项目研究、缓存、推荐输出及未来商业用途的具体授权。
- 本机对许可证正文的直接HTTP回源返回403；上述许可内容来自官方站点的网页读取与搜索索引，不冒充直接回源成功。后续接入前应复核适用版本、账户协议与用途；未核清时不把免费目录列为必然可用的主供给源。
- 品牌规格与营销内容需要分开；目录更新不代表中国地区型号覆盖、销售套餐、价格库存或独立实测已经成立。本轮没有实际查询Icecat商品业务接口。

## 4. 对原四步建议的裁定

| 原建议 | 合理部分 | 建议修订 |
| --- | --- | --- |
| 下载eMCR文本测试中文多条件 | 有标注、可重复，能找出否定和组合条件的失败 | 定位为固定语料检索评测；先查打印机覆盖、字段和许可；隔离答案泄露，限定文本任务，避免全量囤库代替验证 |
| Icecat公开测试/免费目录 | 可验证真实型号详情、结构化参数及更新方法 | 分开验详情与目录发现；先解决本项目用途许可、索引认证、地区/语言覆盖；演示型号不算未知商品自主发现 |
| 导入候选池、复用比较引擎 | 这是应保留的主方向 | 做最小来源/身份/属性适配，保持型号事实与平台销售项分离；不得伪装JD/TB身份、官网来源或实时价格。数值与单位不能一律压成布尔值 |
| 打印机后测陌生品类且不改专用代码 | 能揭露只对打印机有效的假通用性 | 打印机实际链路经独立验证后再做。先验“不改公共引擎，只增加受审配置/数据映射”；零人工配置、自动理解全新品类另列更高目标，不能混签通过 |

新增品类不能只从一个目录覆盖最好、属性最齐的类别挑成功案例。应预先冻结选择理由、需求及失败标准，清楚报告未覆盖类别；一个新类通过也不足以证明全品类通用。

## 5. 更小且能定位瓶颈的下一实验

目标改为：**在打印机一类中，给定用户需求与获准数据源，不提供目标型号/商品ID，系统能发现此前不在本地事实表中的候选，逐项返回有来源的满足、不满足和未知。** 这证明选定来源内的候选发现，不附带宣称全网来源发现或实时可购买。

1. **固定一份独立人工对照。** 先完成原案2–3型号的来源与条件比较审核；冻结约10–20条小任务，区分已有充分事实可给比较的阳性任务、缺证据应暂缓任务及渠道不可用任务。数量为实验建议，并非已完成样本。原案知识缺口不能靠合成“获准证据”填补。
2. **先隔离诊断认知与检索。** 同一任务分别运行“人工核实候选/事实直接提供”与“系统自己检索同一许可范围”。前者也失败，优先修需求转换、品类判断、证据应用或比较接线；前者通过、后者失败，才有依据优先修检索、抽取和身份匹配。若单独补经审品类规则才能改善，再归因为认知证据缺口；不能仅凭最终defer认定根因。
3. **只接一个小来源完成打印机链路。** eMCR用于离线检索对照；真实外部发现使用用途许可明确、实际能取得的来源，可复用已有官方目录能力。不能把eMCR必须覆盖打印机、Icecat必须免费可用作为未经检查的前提。保留实际查询、响应摘要/哈希、型号身份、字段来源与日期；经最小映射进入原比较入口。
4. **阳性和负向一起交独立验收。** 报告已标注候选集内的召回、前三候选逐项硬约束符合度、引用支撑、未知保留、查询次数与耗时；没有全市场真值就不声称全市场召回。加入无匹配、错型号/地区变体、耗材冒主机、缺字段、单位冲突、广告/标签泄露、历史价格冒实时价、条件冲突和诱导下单。错误身份合并、虚构来源、硬条件不满足却声称满足、未经授权交易均应判失败；全部暂缓同样不能证明有用能力。

来源更新能力至少需要两个真实时点/版本或可追溯的真实历史版本差异；单次成功取回资料不是更新已验证。人工构造的变更只能报告为合成同步测试。

独立打印机验收后，再冻结公共引擎，选择一个未参与实现的品类迁移。记录新增了哪些来源、配置、映射及人工工作量；“没有改代码”并不等于“没有人工注入品类知识”。
