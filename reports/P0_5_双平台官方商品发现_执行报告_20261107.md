**状态：离线数据接入与本机回归通过；在线平台授权和实际商品搜索尚未打通。** 这是执行者完成的功能，不是“接通京东/淘宝商品API”或“能在商城自动推荐商品”的证明。

## 一、任务与外部资料（2026-11-07核查）

本轮承接 P0.4 的 Java 商品发现入口与 P0.3 的低信任商品链接导入，目标转向跨品类的**平台商品池**，而不是逐品牌官网找商品。评估者已冻结范围为京东联盟、淘宝客、小红书（拼多多排除）。用户要求执行者有合理自主性，多路径尝试后统一汇报。

1. [京东官方联盟接口介绍](https://jos.jd.com/jdunion)明确 `jd.union.open.goods.query` 可按关键词与SKU等检索联盟推广商品，且接口标注需申请权限。商品池是可推广商品，不是京东所有在售商品。
2. [京东2026开放平台迁移公告](https://jos.jd.com/doc/channel.htm?id=994)明确京东联盟业务接入[独立开放平台](https://union.jd.com/openplatform)。旧 JOS v1 签名/网关代码可作兼容性候选，**不能未经新后台核实就认定当前可调用**。本轮不创建账号、不读取/使用环境密钥。
3. [淘宝官方物料搜索API](https://developer.alibaba.com/docs/api.htm?apiId=35896) `taobao.tbk.dg.material.optional` 标注“不需要用户授权”，**不表示无需开发者 AppKey 与 sign**。官方返回文档中 `num_iid` 已标废弃，`item_id` 是当前商品ID，不能靠老SDK强行回退；材料价/参考价也不等于收货地券后价格、运费和服务费。
4. 京东旧SDK返回对象常用 `jd_union_open_goods_query_responce.queryResult`（注意历史拼写），内层是JSON字符串，内层 `data` 商品列表包括 `skuId`、`skuName`、`priceInfo`、`shopInfo`。具体见项目中现有的[官方接口研究](P0_2_三平台渠道准入与身份验证_20261107.md)；旧SDK结构仅作为**离线契约实验**。
5. 当前项目无可核实的京东/淘宝 AppKey、用途授权、适配平台生产网关或合规评价采集资格。**没有**真实京东/淘宝业务接口调用、没有真实买家登录操作，也没有平台保证的地区报价。

## 二、实际代码落地

- `shopping_decision/jd_union_official.py`：
  - 旧 JOS v1 只读关键词商品查询表单与确定性MD5签名构造（无需网络；密钥不会写入日志/文件）。
  - 解析两层 `queryResult` 字符串 JSON，拒绝网关错误、业务错误、错误字段类型、超大返回、无效SKU和同SKU冲突。
  - 有实际可调用的受控HTTPS POST函数 `query_with_explicit_jd_union_grant`，前置需调用者显式确认**已获该方法业务权限**且**当前旧网关及协议仍允许使用**；固定旧网关地址，无跳转/无重试、请求至多12秒、响应最大256KB；它在当前轮仅用注入的假传输验证，`authorized_api_calls=0`，未对真实平台发起请求。
  - 无论返回价格字段是否存在，结果仍为 `JD_UNION_IMPORT_UNVERIFIED` 且 `quote_verified=false`，不自动进入购买建议。
- `shopping_decision/taobao_material.py`：离线解析官方 `tbk_dg_material_optional_response.result_list.map_data`，只接受当前 `item_id`；旧 `num_iid` 不补齐缺失新ID，商品链接与ID或新旧ID冲突则标记；统一缺价、地区库存等信息为未知。**还没有**淘宝真实签名请求端的执行。
- `shopping_decision/discovery_pool.py`：汇总 JD联盟导入、淘宝物料导入与 P0.4 用户手选 JD 商品链接。**同一JD SKU可合并来源但不据此认定商品身份相同；JD与淘宝即便数字ID相同也绝不合并。** 品牌+型号标题锚点只作为厂商规格回查线索，不能证明是主机还是配件。禁止把上游 `purchasable=true` 或价格信息带入可靠购买状态。
- `shopping_decision/listing_identity.py`：修复中文品牌名紧贴拉丁型号时的标题锚点边界问题，仍能区分 HL-L1238W 与 HL-L1238WXL。
- `shopping_decision/discovery_ingest.py`：更新 JD_UNION/TAOBAO_TBK 的离线导入能力状态为 true；**实际授权、真实环境验证、地区核价依旧 false**。

新增三套测试：`tests/test_jd_union_official.py`（24例）、`tests/test_taobao_material.py`（14例）、`tests/test_discovery_pool.py`（12例）。这些测试全部基于**合成**输入；不含平台账号、Cookie、真实价格或新发交易。

## 三、可复现实验与验收

### 合成端到端回放

文件 `reports/P0_5_多源合成回放_20261107.json`，显式标注 `SYNTHETIC_ONLY_NOT_REAL_PLATFORM_PRODUCTS`。同一个京东SKU有两条来源（JD联盟格式与用户手选链接），淘宝物料使用**相同数字ID**：

| 指标 | 本轮合成结果 |
|---|---:|
| 候选销售项（按平台+ID） | 2 |
| 京东候选的来源记录 | 2 |
| 淘宝候选的来源记录 | 1 |
| 已核实地区到手报价 | **0** |
| 原购买批准/交易能力 | **关闭** |

每条商品标题可能被误用为配件或套餐的依据，只能返回 `title_anchor_only_unverified` 或冲突待核，不能给出“已经找到值得购买的型号”。

## 四、执行者选定的下一路线，不需要评估者教怎么重试

优先做**有限的官方真实商品检索**，但有严格前置：

1. 先通过[京东联盟独立平台](https://union.jd.com/openplatform)确认主体能否取得应用、`goods.query`权限、合法展示/对比用途、生产网关/签名版本；不要自动用旧JOS v1推断合法权限。得到授权以后，配置本机临时凭证、只发2–3个只读关键词/详情请求，映射到同一候选池，保存不含凭证的响应哈希、字段缺口，不做任何下单。
2. 如果京东资质未到位，不停工：淘宝官方物料接口是第二条，但同样需要应用Key/签名及业务场景资格；可以对已授权的淘宝响应采用当前解析器进行同条件对照。
3. 如果两条官方路线都暂无授权，不应继续在无授权接口上碰撞；第一版继续使用**用户自己在浏览器打开商城搜索、自选少量商品链接**的 P0.4 实际入口。这个降级入口只能扩充候选**线索**，不等于自动发现、自动核价。
4. 下一工程任务是取得**少量真实、允许留存/展示的两平台响应**，检查目标商品覆盖率、型号/变体/卖家字段与新旧ID一致性，并由独立评估者验收。无需重新做品牌官网采集器或大规模架构重构。
