# 开源购物智能体怎样从认知走到推荐：源码调研
日期：2026-11-15；角色：研究评估者。

这次问题是：现有购物智能体是否先帮助用户弄懂“该怎么选”，是否依据消费者组织、监管机构、专业测试和社区资料，再据此推荐商品。

结论：已有项目实现了其中不同部分，可以借鉴；本次审读的项目中，未核实到一个已经稳定打通“中国权威资料→有出处的品类选购依据→个性化条件→真实商品核验→推荐”的完整现成方案。这个结论仅覆盖本次样本。最接近证据研究约束的是 NorthCinder；最值得借鉴通用筛选代码的是 NVIDIA 的零售购物助手。两者都不能据此宣称可以直接替代本项目。

## 2. 各项目实际怎样做

### 2.1 NorthCinder：先研究具体商品，再判断证据是否足够

实际链路：
用户用途及不可妥协条件 → 确认具体型号/版本/地区/配置 → 创建研究清单 → 宿主智能体用自己的搜索或浏览工具取证 → 提交带出处的事实记录 → 程序校验对象绑定、清单、冲突和缺件 → 返回候选比较及待核实事项。

源码证据：
- [商品研究指南](https://github.com/cinderline/northcinder/blob/d1343096a7afff58e0aee4fbf608daf2fa28dc03/client/research-skills/product-research/SKILL.md#L19)：要求先明确用途、具体版本，分别查厂家/说明书、独立测量、真实使用者报告，并隔离商家及返佣内容；还要求主动搜索反证。
- [创建研究计划工具](https://github.com/cinderline/northcinder/blob/d1343096a7afff58e0aee4fbf608daf2fa28dc03/client/src/server.ts#L386)：返回固定研究清单、查询/阅读上限、证据必要字段；它本身不是自动生成各品类专业知识的工具。
- [提交证据工具](https://github.com/cinderline/northcinder/blob/d1343096a7afff58e0aee4fbf608daf2fa28dc03/client/src/server.ts#L890)：限定在本次搜索返回的商品内提交，校验结构及清单标识。
- [就绪状态计算](https://github.com/cinderline/northcinder/blob/d1343096a7afff58e0aee4fbf608daf2fa28dc03/client/src/decision-evidence.ts#L82)：型号不明、费用不全、缺商品或卖家证据、清单未闭合、冲突及未知项等会使结果保持 provisional（待核实）。
- [排序说明](https://github.com/cinderline/northcinder/blob/d1343096a7afff58e0aee4fbf608daf2fa28dc03/docs/RANKING.md#L53)：研究证据改变就绪状态，不直接加排序分；排序另有公开规则。

值得借鉴：把“我查到了什么、还缺什么、是否同一具体商品”变成能检查的记录；不把多写几段研究文字当成高分商品。

限制：
1. [README](https://github.com/cinderline/northcinder/blob/d1343096a7afff58e0aee4fbf608daf2fa28dc03/README.md#L33) 明确表示，目前没有通过常规研究使用资格验证的宿主/模型组合，研究结果仍需买家检查。不能将研究指南和代码门槛当成成熟效果证明。
2. 搜索由宿主执行，不等于项目自带消费者协会/中国监管机构连接器。
3. 程序能校验字段及一致性，不能仅凭提交者标记“独立”就证明来源独立，更不能自动证明文章内容为真。
4. 清单以具体商品研究为主，仍不是已经验证的“先学习整个品类，再自动生成专业字段”的通用认知系统；固定排序权重也不能直接移植为所有品类的最优规则。

### 2.2 NVIDIA：把“有哪些字段、哪些条件可过滤”告诉智能体

实际链路：
预先整理商品资料及字段含义 → 程序读取并校验 → 发布当前商品库的字段/可选值/范围等能力 → 智能体把需求转成可执行条件 → 程序过滤与检索 → 智能体解释候选，必要时追问或请求放宽条件。

源码证据：
- [商品库架构](https://github.com/NVIDIA-AI-Blueprints/retail-shopping-assistant/blob/3eca0719c130ecd840ece67b8f285b15a795312b/docs/CATALOG_ARCHITECTURE.md#L1)：商品行与字段含义描述分离；新增类别/值主要依赖数据，新字段需要描述。
- [字段描述样例](https://github.com/NVIDIA-AI-Blueprints/retail-shopping-assistant/blob/3eca0719c130ecd840ece67b8f285b15a795312b/shared/data/enriched_products.schema.yaml#L1)：明确数值、枚举、列表以及能否作为过滤条件。
- [能力发现代码](https://github.com/NVIDIA-AI-Blueprints/retail-shopping-assistant/blob/3eca0719c130ecd840ece67b8f285b15a795312b/catalog_retriever/src/capabilities.py)：从当前商品快照生成能力信息。
- [选品指南](https://github.com/NVIDIA-AI-Blueprints/retail-shopping-assistant/blob/3eca0719c130ecd840ece67b8f285b15a795312b/orchestrator/skills/shopper/product-discovery/SKILL.md#L18)：把硬条件与偏好分开；无匹配不偷偷忽略条件。

值得借鉴：同一个比较器可以按不同品类的数据描述处理条件，不必每换一种商品就复制一套相等、大于、小于判断。

限制：所读主链路面对的是已整理好的商家商品库，没有展示自动从中国消费者组织和监管资料生成品类选购依据。字段描述从哪里来、是否有证据，仍需另做。本项目也不能因此把厂家宣传当专业测评，或把库内价格当地区实时到手价。它是参考实现，部署依赖及模型/数据条款须单独评估。

### 2.3 球球：有“品类教育”，但主要是提示词规定的行为

实际链路：
用户问题 → 本地商品/问答/评论检索 → 改写问题及识别场景 → 按提示词选择教育追问、推荐、比较或评价 → 生成回答。

源码证据：
- [系统提示词](https://github.com/pingfangww/qiuqiu-rag-shopping-agent/blob/a0ac29eeb596ae06d4c71e29b4600ce6973e21de/server/agent/prompts/system_prompt.md#L15)：明确要求需求不清时先教育再追问。
- [路由条件](https://github.com/pingfangww/qiuqiu-rag-shopping-agent/blob/a0ac29eeb596ae06d4c71e29b4600ce6973e21de/server/agent/prompts/system_prompt.md#L49)：是否追问还与检索到的同类商品数量有关，是产品数量启发式。
- [检索器](https://github.com/pingfangww/qiuqiu-rag-shopping-agent/blob/a0ac29eeb596ae06d4c71e29b4600ce6973e21de/server/rag/retriever.py#L71)：本地向量库及商品元数据，部分品类关键词/场景槽位写在代码中。

值得借鉴：交互顺序与你说的认知环节一致，先解释影响购买的分歧，再问能缩小范围的问题。

限制：所读链路没有证明“选购指南的每个依据都来自可追溯权威资料”，也没有证明教育结果已经变成驱动比较程序的品类规则。流畅的选购教育仍可能来自模型常识、提示词示例或商品材料。当前未取得明确主体许可证；按仓内规则仅审读方法，未复制源码/数据。

### 2.4 ShopSense：先搜索市场，再收敛到具体型号和销售页

实际链路：
读取预算/偏好 → 网络搜索 → 缩小到少量型号 → 搜索型号与商店价格 → 必要时提取商品页 → 比较并给链接。

源码证据：
- [研究与推荐提示词](https://github.com/raghav-malik/ShopSense/blob/f7ba10af8c0251146449c90b28816a6be867996e/app/agent/prompts.py#L61)：规定推荐前必须搜索、使用商品页链接、围绕候选继续查价。
- [主循环](https://github.com/raghav-malik/ShopSense/blob/f7ba10af8c0251146449c90b28816a6be867996e/app/agent/core.py)：执行工具循环、调用预算及价格检查。
- [搜索工具](https://github.com/raghav-malik/ShopSense/blob/f7ba10af8c0251146449c90b28816a6be867996e/app/tools/search.py)：通用网页搜索，当前默认区域为印度英文。
- [比较工具](https://github.com/raghav-malik/ShopSense/blob/f7ba10af8c0251146449c90b28816a6be867996e/app/tools/compare.py)：消费已有候选信息，不是自动建立专业评测标准的模块。

值得借鉴：先广搜再收敛、避免无止境查询，以及预算/偏好在会话中的保留。

限制：所读链路没有形成权威来源资格、独立性审查、品类研究到比较条件的完整合同；提示词也允许依赖搜索片段中的价格。它的页面价格检查不能直接视为本项目“具体配置+卖家+地区+优惠条件+当前时刻”的权威核价已解决。许可证仍待明确。

### 2.5 Open Deep Research：可以借鉴查资料的方法，不能当完整购物助手

实际链路：
澄清研究问题 → 形成研究任务 → 分解与循环检索 → 阅读网页补缺 → 压缩证据 → 生成带引用报告。

[研究提示词](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/prompts.py#L44) 提到商品研究优先官方/原始网站，并记录指定来源；[调度源码](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/deep_researcher.py#L60) 展示澄清、研究任务、检索循环和报告生成。

值得借鉴：认知资料不足时继续查证，而非立刻给商品榜单。限制：本次仓库已归档；它不会自动完成商品身份、独立性、单位一致性或实时价格核验。只借鉴研究方法，不建议为了此次认知环节整体换框架。

## 3. 用户提出的权威来源怎样真正参与推荐

你的设想合理：认知阶段应有外部证据，不应完全依赖模型记忆。需要修正的是“权威来源”并不能统一回答所有购买问题，必须让资料支持其有资格支持的具体结论。

| 来源 | 适合回答 | 不应由它直接推出 |
| --- | --- | --- |
| 消费者协会/消费者委员会的比较试验 | 哪些维度影响使用、如何测、受测具体型号在特定条件下的表现 | 旧样本覆盖今天所有型号，或海外版本等于大陆销售配置 |
| 市场监管部门的抽检/召回信息 | 哪个具体产品/批次出现何种问题，查验需要哪些身份信息 | 没被点名就安全，或抽检合格就最适合买 |
| 药监局公开查询（仅适用其监管品类） | 对应产品的注册/备案等记录 | 有记录就有最佳效果、最适合此人；也不应套到手机、打印机 |
| 厂家说明书、规格及保修条款 | 具体型号的接口、功能、尺寸、适用配件、服务条件 | 广告中的体验承诺就是独立测试结论 |
| 专业独立测试 | 特定方法下的续航、速度、成像等实际表现 | 不同方法/版本/环境得到的数值可直接横比 |
| 高质量使用帖及评论 | 长期维护、使用环境、常见不便及值得进一步调查的故障线索 | 点赞多即真实独立，几条差评即可估计全体故障率 |
| 平台/商家的当前销售记录 | 具体所选配置、卖家、当时价格、库存、适用优惠及售后 | 用搜索摘要、旧评测价格替代当前地区到手价 |

本次核到的实际例子：
- [香港消委会打印机比较试验](https://www.consumer.org.hk/sc/article/598-multifunctional-printers/598-multifunctional-printers-test-items-and-results) 涵盖打印/扫描/复印质量及速度、使用便利等项目，可以帮助形成“应比较什么”的清单；这是具体历史测试，不能冒充当前大陆采购榜单。消费组织资料的全文、数据库再利用或批量采集权限仍须逐源核查。
- [市场监管总局2022年电子产品抽查通报，2023年发布](https://www.samr.gov.cn/zljds/jdcc/art/2023/art_1036ff5727d248e18dc2bcd58f7e5d4b.html) 中打印机项目侧重安全与电磁兼容等检查，说明它与“耗材成本/彩印体验哪款合适”是不同证据。
- [国家药监局数据查询帮助](https://datasearch.nmpa.gov.cn/datasearch/search-help.html) 与 [化妆品官方栏目](https://www.nmpa.gov.cn/hzhp/index.html) 的搜索索引可核查询入口类型；本次直接读取分别超时/返回412，未核实时产品记录、API或自动采集能力。不据此声称已接通。

没有找到某型号，不等于它没有问题；没有查到备案也不能立即认定违法，需先排除名称、版本、查询入口、数据时效和读取失败。这里讨论证据使用方法，不作具体商品合规或医疗结论。

## 4. 怎么接到本项目的“认知→通用比较”中

下面是基于源码审读提出的方法，不是本轮已经实现的能力。

资料研究 → 有证据的品类选购依据 → 用户需求匹配 → 商品事实核验 → 通用条件检查 → 少量候选及有条件的取舍解释。

关键交接物应当是“可检查的选择依据”，不能只有一篇选购文章。每条至少包含：
1. 要关心的问题，及它为何会影响当前用户的使用。
2. 需要问用户的条件，以及用户尚未提供的信息。
3. 所需商品字段、字段类型/单位、适用版本/测试环境。
4. 如何处理：硬条件、软偏好、可复算的成本，或需要证据解释的体验取舍。
5. 支持/反对证据、来源、发布/获取日期、适用范围、失效条件及未知项。

程序执行经过审核的比较方式，例如预算上限、是否支持彩印、集合包含、区间关系、证据是否过期、版本是否一致；不执行模型随意生成的代码，也不允许它临时捏造运算符或比较标准。复杂体验判断不能被强行变成大小比较。

换品类能够复用的是字段校验、单位归一、条件执行、缺件处理、证据绑定和审计记录；仍需重做并审核的是品类知识、问题、证据来源及字段解释。自动提取可以先产出草稿，不能等同自动认定行业共识。

以两个假设需求说明，均非商品推荐：
- 打印机：用户明确必须彩印 → 形成彩印硬条件；商品的确切型号事实若为仅黑白，则排除，不能被“支持扫描/双面”救回来。关注成本时，还需印量、使用期限、耗材及保养假设，不能单看机器价格。
- 手机：用户关注续航 → 需要适用场景下的续航证据，不能仅以电池容量大小推出体验高低；不同亮度、网络、系统版本的测试先判可比性。若缺可比数据，则保留未知，而非硬填总分。

这部分分别借鉴 NorthCinder 的证据记录/待核实状态、NVIDIA 的字段描述/通用过滤和深度研究的补缺方法。并不是拼接几个项目就自动得到可靠消费者顾问。

## 5. 对当前瓶颈的具体意义

本次结果支持继续做认知与比较的交接合同，不支持马上换框架、开发手机或扩充更多合成流程。

与 CURRENT 最新验收对应：
- F1 硬条件已排除的黑白机仍被扫描/双面理由激活：先让所有入口使用一致的硬条件结论。
- F2 预算变化后解释与表格未更新、F3 印量关系写反：同一轮输入、条件计算和解释必须同源重算，不能把固定话术当认知结果。
- F4 异常价格输入溢出：数据类型/范围的通用防护应隔离坏行，保留合法邻居。
- 海纳用途/可审真实内容及两个真实销售配置仍缺：开源架构不提供这些证据，也不自动消除权利及接入缺口；权威资料可补充研究依据，不能冒充平台销售身份及实时核价。
