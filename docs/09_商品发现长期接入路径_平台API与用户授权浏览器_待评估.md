## 一、把当前瓶颈分成三个不同能力

- **商品发现（Discovery）**：从真实在售平台商品池检索品牌、型号、销售项和平台标识。2026-11-10 起已有海纳商品检索 Pro 真实调用作为可用第三方发现入口；京东联盟/淘宝联盟官方 API 仍是可选的直连路线，不再是当前唯一的候选发现路径。品牌官网仍主要承担型号与规格事实核验，不替代商城销售项发现。
- **商品核验（Verification）**：厂家官网核对规格、连接方式、耗材兼容性；平台详情核对店铺、具体 SKU/套餐、价格与地区库存、优惠资格；评论/横评核对用户体验。这三种证据不能互相替代。
- **用户实际购买条件（User-specific offer）**：授权登录的浏览器可作为少量销售项的核验入口；**用户登录并不意味着获得全站商品 API 或自动批量采集许可**。账号凭证不离开本机，不跨域外传；浏览器页面操作按逐次用户授权，遇登录限制/验证码即停止，购物车/下单/支付不做。

## 三、开源项目能借鉴什么

1. [microsoft/playwright-mcp](https://github.com/microsoft/playwright-mcp)：已登录浏览器连接、规范化页面交互和受控状态，适合**用户参与的商品核验路径**。需另审使用条款与权限范围。
2. [abc354402600/JD-Shopping-MCP](https://github.com/abc354402600/JD-Shopping-MCP)：公开京东搜索、商品、价格工具的接口样例，但其 README 明确搜索会回退 Bing、公开价不含地区/PLUS/券后价，仓库很新且未发现可确认许可证；**仅研究接口设计，暂不复制源码或依赖其真实报价**。
3. [TonyWang-hub/mcp-cn-commerce](https://github.com/TonyWang-hub/mcp-cn-commerce)：MIT、8平台的商家经营数据连接器，当前公开说明 SDK 真店验收未完成；可借鉴多平台 Adapter、权限、限流、脱敏、字段缺失与可追踪性，**不是消费者商品发现接口**。
4. [Vael-KY/AI-Shopping-auto](https://github.com/Vael-KY/AI-Shopping-auto)：Apache-2.0，展示浏览器搜索与支付宝支付的分层组合；本项目只研究只读搜索部分，支付/下单桥接不复制。

## 四、执行者原建议（2026-11-07；海纳实测后由评估者重新排序）

> 下方流程图保留 11-07 原方案的结构。2026-11-10 起，海纳商品检索 Pro 已成为新增的可调用商品发现入口；图中未体现这一新增来源，不应再按原图把 JD/淘宝官方 API 或用户授权浏览器视为发现商品的唯一入口。

```text
用户输入任意商品需求
   │
   ▼
按需生成品类选择条件（硬条件、预算、用途）
   │
   ├─ JD 联盟官方 API（获准后）──┐
   ├─ 淘宝联盟官方 API（获准后）─┼─> 标准化平台销售项
   └─ 用户明确授权浏览器（适用时）┘      │
                                         ▼
                                   型号/套餐/店铺防错绑
                                         │
                    ┌────────────────────┴───────────────────┐
                    ▼                                        ▼
              厂商型号事实校验                         评价/专业横评/反证
                    └────────────────────┬───────────────────┘
                                         ▼
                        硬约束/售价资格/库存/证据三态门禁
                                         ▼
                   候选比较或 defer（没有价格不能说“可购买”）
```

**11-07 原建议的适用边界**：当时尚无真实商品搜索 API 响应，因此把官方 JD/淘宝 API 准入与用户授权浏览器作为候选验证路线。2026-11-10 海纳商品检索 Pro 已完成首轮真实调用，商品发现入口现已打通；是否优先做海纳 Adapter、商品身份核验、报价验证或条款核对，交本轮评估者根据整体瓶颈决定，不在此预设。无论选择哪条路线，每个真实销售项仍需尽量保留：平台/URL/商品 ID、型号与所选配置、卖家、价格类型与附加费用、地区/库存、获取时刻、出处。信息不全即未知，不应进入已核报价。

- **AC-A：** 不预埋品牌官网为全局主入口，查一个全新未知品类时应仍能经平台搜索入口找候选（允许未知），不需为每个品牌改代码。
- **AC-B：** 同名异型号、裸机/耗材/套装、USB/无线混淆必须拒绝或待核；不同平台商品 ID 不自动互换。
- **AC-C：** 真实商品发现数量和“地区到手价可验证数量”分别报告；用人工输入/假数据做测试时明确标记。
- **AC-D：** 使用浏览器时，只读行为必须被逐次许可并保留可审计动作，禁止跳过登录/验证码或将账号会话上传仓库。
- **AC-E：** API 与浏览器两路都阻塞时，输出已测试路径、可复核失败证据、一个执行者选定的安全替代方案，交评估者**做独立判断**而非请其给出检索步骤。

**当前阶段（截至 2026-11-10）**：海纳商品检索 Pro 已完成一次真实业务 API 调用，第一阶段商品发现入口已打通；但海纳接入本地项目代码尚未完成，覆盖范围、商品身份、销售项、价格口径和使用授权仍待评估。京东/淘宝官方直连 API 的本应用资格仍单独待核；用户辅助浏览器仍是少量具体销售项核验备选。不得将搜索结果认定为有效地区报价或购买资格，不提升交易权限、不修改购买批准字段、不推送远程。
