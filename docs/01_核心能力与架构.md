# 核心能力与架构

## 1. 解决什么问题

传统购物 Agent 是「按关键词检索 → 排序 → 点击购买」。本项目要求先回答：
- 这个品类有哪些底层技术路线、长期成本和常见坑？
- 用户的场景如何决定技术路线？哪些条件缺失会改变结论？
- 某个推荐有何正反证据，是否依赖过期数据或商业推广？
- 确定适配型号后，能否核验实际 SKU、到手价、售后等动态信息？

商品之外可扩展到服务（培训、保险咨询等需额外合规门禁）和旅行预订；**先通过打印机类目验证可迁移性**，不要提前造通用购买平台。

## 2. 业务主链及模块

| 环节 | 核心输入 | 核心输出 | 检查点 |
|---|---|---|---|
| S1 需求理解 | 自然语言、历史约束（仅有授权的） | 结构化场景、硬约束、待澄清项 | 缺少关键条件不得硬推 |
| S2 品类认知 | 场景、品类名 | 技术路线、可核查知识主张、例外 | 来源、时效、适用条件 |
| S3 证据合成 | 知乎/小红书评测、厂商资料、用户评论 | 支持/反证、争议、可信度 | 推广与测评区分；独立来源 |
| S4 路线决策 | 需求 + 知识 | 路线推荐 / 暂不决策 | 解释为何不选其他路线 |
| S5 商品筛选 | 选购路线 + 预算 + 型号 | 经核验 SKU、评论证据与动态报价 | 无来源不能填价 |
| S6 方案输出 | 候选清单 | 排序、总拥有成本、风险、购买建议 | 不编造具体商品 |
| S7 交易草稿 | 用户选中商品 | 订单意图草稿 | 只读默认；副作用逐级授权 |
| S8 安全交接 | 草稿、授权上下文 | 外部支付实验台输入 | 委托、绑定、幂等、日志 |

## 3. 两条知识路径

**路径 A：百度优选品类知识服务（外部接口）**
- 品类知识/商品百科、榜单、商品理解、商品搜索，适合接入权威的结构化参数和商品数据。
- 作为可选 provider，不掌握用户规则的最终解释权；未授权/网络断开必须可降级。
- 不假设平台提供任意商品的免费交易 API，具体需按官方开放平台申请权限。

**路径 B：球球式可控本地认知（自建知识库）**
- 用户意图/澄清、中文向量检索、产品属性过滤、评价片段召回、二阶段排序、跨商品对比。
- 上游主要演示商品推荐与模拟下单；我们重点复用其交互/检索设计，不照搬单体 Prompt 或假设真实平台可下单。
- 稳定品类知识与商品事实分离：专业测评知识存证据层，型号/价/库存仅由商品适配器提供。

最终由**认知协调器**并行或按需调用 A 和 B，合成带证据的结论；发生冲突时标注冲突而非简单多数票。

## 4. 最小领域契约

```text
PurchaseRequest {category, budget_max, usage, required, optional, excluded, clarification_state}
KnowledgeClaim {claim_id, subject, predicate, applies_when, exceptions, evidence_ids}
Evidence {source_id, source_type, url, published_at, captured_at, excerpt, sponsor_flag}
ShoppingRoute {route_id, fit_reasons[], tradeoffs[], evidence_ids[]}
ProductCandidate {platform, product_id, sku_id, price_quote?, facts[], source_ids[]}
Recommendation {status, recommended_route?, candidates[], reasons[], counter_evidence[], unknowns[]}
OrderDraft {recommendation_ref, platform, sku, quantity, quote_snapshot, consent_required=true}
```

这里是形状定义，**并不表示实际平台接口已经打通**。不可写入账号密码、Cookies、会话令牌、收货地址等真实个人数据。

## 5. 设计取舍

- 不在第一阶段开发 App：先有可量化的决策质量、可观测轨迹，再选浏览器、Web 或 Android。
- 不在首轮引入微服务/重型多 Agent：一个编排器 + 可插拔知识/商品/评测接口先验证主瓶颈。
- 不把付费 API 当已开源资产：百度当外部服务，球球与双评测项目当参考；引入源码需逐项做许可审查。
- 和 agentic-payment-trust-lab 的交接必须是**标准化订单意图**，不直接共享真实消费者资金凭证。
